# club-server

Серверная часть гибридного бездиска для компьютерных клубов: Windows стоит локально на каждом ПК, по сети
раздаётся только библиотека игр — read-only iSCSI-том (клон ZFS) с TrueNAS SCALE 25.10+.

Сервер **не зависит от шелла**: касса, игроки, сессии, тарифы и деньги — зона шелла (ClubShell, Senet,
iCafeCloud и т. п.). Со стороны ПК с сервером работает только наш помощник бездиска (служба Windows).

.NET 10, PostgreSQL 18, TrueNAS SCALE 25.10+.

```

src/Club.TrueNas     JSON-RPC-клиент middleware TrueNAS (wss, API-ключ, закреплённая версия API) и операции с томами/iSCSI
src/Club.Helper.Core логика помощника бездиска (Linux-тестируемая)
src/Club.Helper      помощник бездиска — служба Windows (docs/helper.md)
docs/diskless-api.yaml  спецификация API бездиска (OpenAPI 3.1); .json генерирует scripts/build-spec.sh
docs/panel-api.md    API панели администратора
docs/network.md      Kea DHCP: адресный план, установка, резервации, чужой DHCP
docs/imaging.md      образы Windows и перезаливка по PXE (iPXE, wimboot, WinPE)
docs/master-editing.md  правка игр на мастер-томе (суперклиент)
docs/install/stand.md  установка стенда по этапам (Ubuntu, TrueNAS, помощник, библиотека, Kea)
deploy/              unit systemd и пример настроек сервера; scripts/server/make-club-ca.sh — CA клуба

docs/research/       исследование API TrueNAS и стека .NET (источники и статусы проверки)
```

## Что реализовано

- **API бездиска** (`/diskless/v1`, `docs/diskless-api.yaml`): регистрация машины по `X-Club-Key` и HWID (номер места
  выдаёт сервер, MAC для DHCP/PXE), JWT RS256 и одноразовый refresh, «какой том монтировать», отчёт помощника о
  фактическом состоянии тома (в ответе — актуальный том). Отчёт отмечает машину «на связи» — по нему считается подписка.
- **Библиотека игр** (`src/Club.Server/Library`, секции `Library` и `TrueNas`): версии хранятся как намерения в БД,
  операции publish/rollback — в журнале; единственный фоновый исполнитель (advisory lock). Публикация: снапшот
  мастер-zvol → RO-клон → extent (ro) → target с версией в имени → LUN → новая версия текущая, прежняя — откатная,
  ещё более старая разбирается (таргет без force: пока ПК подключены — ждём). Недоступный TrueNAS не тратит попытки,
  падение на любом шаге — операция выполняется заново. Сверка только пишет предупреждения (`storage_warnings`).
- **API панели** (`/panel/api/v1`, `docs/panel-api.md`): обзор библиотеки, публикация, откат, повтор упавшей операции,
  предупреждения. Доступ пока по одному токену `Panel:AdminToken`.
- Миграции FluentMigrator с откатом; тест прогоняет откат до пустой базы и обратно.

- **Помощник бездиска** (`docs/helper.md`): служба Windows, монтирует том read-only fail-closed, переключает версии
  без выдёргивания диска из-под игры, при недоступном сервере — последнее назначение. Windows-часть на стенде
  ещё не проверялась.
- **Панель** `/panel/` (ru/uz/en, без сборки): «Рабочие станции» — реестр машин, одобрение новых, номер места, зона,
  обслуживание, состояние тома на каждом ПК; «Библиотека игр» — версии, публикация, откат, ход операций, сколько ПК
  на какой версии, состав версии; «Образы Windows»; «Сеть» — адресный план, резервации DHCP, плашка чужого DHCP.
- **Kea DHCP** (`docs/network.md`, секция `Kea`): резервации IP по номерам мест в базе Kea (hosts backend PostgreSQL),
  ручные резервации не трогаются, генерация `kea-dhcp4.conf` (проверяется `kea-dhcp4 -t`), детект чужого DHCP по
  отчётам помощников. Установка Kea и конфига — вручную от root.

- **Образы Windows и перезаливка** (`docs/imaging.md`, секция `Imaging`): импорт install.wim (разбор WIM, sha256),
  текущая и откатная версии; перезаливка из панели — PXE-флаг классом в резервации Kea, iPXE + wimboot + WinPE,
  скрипт заливки по плану сервера (какой диск стирать — только системный), флаг снимается только после bcdboot.
  Проверено на настоящей Kea 3.0.3 (в сетевом пространстве без root) и скриптом WinPE в PowerShell с заглушками.
- **Правка игр — суперклиент** (`docs/master-editing.md`): мастер-том на запись одному ПК администратора (CHAP с новым
  секретом + группа из его IQN), помощник подключает его как `M:`, закрытие ждёт сброса и отключения, публикация
  запрещена, пока том открыт; принудительное отключение помечает том «возможно, недописан».
- **Secure Boot** (`docs/research/secure-boot-pxe.md`): подписанная цепочка shim iPXE (Microsoft) → iPXE → wimboot →
  WinPE, установка `scripts/pxe/install-boot-files.sh` (закреплённые версии и sha256), проверка подписей Authenticode
  на сервере, загрузчик Windows CA 2023 для ПК с отозванным PCA 2011, отказ заранее, если ПК не загрузится.

Не сделано: проверка помощника, Kea, заливки и Secure Boot на стенде; USB-обёртка образа, активация Windows;
остальные экраны панели, вход в панель по учётным записям.

## Запуск

```bash
createdb club_dev
ASPNETCORE_ENVIRONMENT=Development dotnet run --project src/Club.Server --urls http://127.0.0.1:5080
```

Тесты (нужен локальный PostgreSQL с правом CREATEDB у текущего пользователя):

```bash
dotnet test ClubServer.sln
```

Необязательные проверки на настоящих программах (без них соответствующие тесты ничего не проверяют):
`KEA_DHCP4` (+ `KEA_HOOKS_PATH`, `LD_LIBRARY_PATH` для распакованного пакета) — Kea: `kea-dhcp4 -t` и выдача
загрузчика в сетевом пространстве `unshare -r -n`; `PWSH` — скрипт заливки WinPE в PowerShell; `IPXE_BUNDLE`
(распакованный), `IPXE_BUNDLE_TGZ` и `WIMBOOT` — подписи настоящих файлов iPXE/wimboot и скрипт их установки.
