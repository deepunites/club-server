# Самообновление помощника бездиска (ClubDisklessHelper 1.8.0) — спецификация

Дата: 2026-11-06. Статус: на утверждении у владельца клуба.

## 1. Что нужно клубу

Обновлять помощник на ПК без человека у ПК. Сейчас каждое обновление — вход `Club` с Shift на каждом гибриде и строка
`update-helper-net.ps1`; на 22 гибридах это обход всего клуба.

Решения владельца (2026-11-06):

- Обновление запускается **кнопкой в панели** сервера клуба: для выбранных ПК или для всех гибридов; не автоматически.
- Помощник перезапускается на новую версию **между сеансами**: пока у игрока выданы сохранения, он ждёт конца сеанса.
- Способ замены — «А»: служба сама кладёт новый exe рядом, меняет файлы местами и выходит; Windows перезапускает
  службу уже новой версией. Новая версия, которая не запускается, сама возвращает прежнюю.
- Раскатка: не больше 3 ПК одновременно, очередь останавливается на первой ошибке.
- Бездиск: обычные места кнопку не получают (C: сбрасывается при загрузке); мастер эталона в сеансе мастера — получает
  (обновление попадает в эталон, дальше `seal-golden` и публикация).
- 1.8.0 ставится на ПК последний раз вручную; дальше — кнопкой.

Критерий готовности: на гибриде PC-22 с 1.8.0 кнопка в панели ставит пробную 1.8.1 без человека у ПК, панель
показывает «готово» и сборку 1.8.1; пробная сборка, которая не запускается, сама откатывается на прежнюю, панель
показывает «ошибка», очередь остановлена; G: и H: при этом не отключаются.

## 2. Как это работает

```
панель ── «обновить ПК 11-20 до 1.8.1» ──► сервер: поручения в очереди (helper_updates)
                                             │  отчёт ПК раз в 30 с; не больше 3 активных
ПК ◄── ответ на отчёт: helperUpdate {версия, SHA256, размер, путь} ──┘
помощник: скачивает .new в фоне → SHA256 → ждёт свободного момента → .old/.new местами → выход
Windows (действия при сбое службы): через 5 с запускает службу → новая версия
новая версия: первый принятый отчёт = здорова → стирает .old, сообщает SHA256 своей сборки → сервер: «готово»
не запускается 3 раза подряд → возвращает .old → прежняя версия сообщает «ошибка» → сервер: очередь на паузу
```

Принцип API не меняется: сервер не управляет Windows, он сообщает желаемую сборку в ответе на отчёт (как назначение G:
и мастер-тома); когда и как её ставить, решает помощник и сообщает факты.

## 3. Сервер клуба (Club.Server)

### 3.1. Сборки

- Сборки лежат в `tools` раздачи PXE: `<Imaging:PxeRoot>/tools/ClubDisklessHelper-<X.Y.Z>.exe` (как сейчас; кладёт
  администратор, файлы root, сервер только читает). Имя — строго `^ClubDisklessHelper-\d+\.\d+\.\d+\.exe$`, версия
  берётся из имени.
- Сервер сам считает SHA256 и размер каждой сборки (кэш по размеру и времени изменения файла).
- Сборка задаётся в поручении по имени файла; в поручение записываются версия, SHA256 и размер на момент запуска. Если
  файл потом заменили (другой SHA256) — активное поручение по нему завершается ошибкой `buildChanged` (проверяется при каждой выдаче поручения).

### 3.2. Данные (миграция `M0013_HelperUpdates`, id `2026110601`)

- `machines.helper_build text NULL` — SHA256 exe, который сообщил помощник (1.8.0+), строчными hex.
- `helper_updates`: `id uuid`, `machine_id` (FK, каскад), `file`, `version`, `sha256`, `size bigint`,
  `state` (`queued`, `paused`, `active`, `done`, `failed`, `cancelled`), `progress` (последнее состояние от помощника:
  `downloading`, `waiting`, `applying`), `error`, `requested_by`, `created_at`, `updated_at`, `finished_at`.
  Не больше одного незавершённого поручения на ПК (частичный уникальный индекс по `machine_id` для `queued`, `paused`,
  `active`).

### 3.3. Очередь

- Поручение становится `active` в момент отчёта своего ПК, если активных меньше `HelperUpdates:MaxActive` (по умолчанию
  3) и в очереди нет паузы. Выключенные ПК места в очереди не занимают; включатся — получат поручение.
- `active`, ПК которого не отчитывался 10 минут, возвращается в `queued` (место освобождается).
- `done` — когда отчёт ПК содержит `helperBuild` = SHA256 поручения.
- `failed` — когда помощник сообщил ошибку по этой сборке. Тогда все `queued` переходят в `paused`; в панели —
  «Продолжить» (`paused` → `queued`) и «Отменить».
- «Отменить» — `queued`, `paused` и `active` → `cancelled`; сервер перестаёт присылать поручение. Если помощник уже
  меняет файлы, он заканчивает замену (поручение остаётся `cancelled`, сборка ПК видна в панели).
- Завершённые поручения видны в панели сутки.
- Кому можно: ПК одобрен, `boot_mode = local`, или это мастер эталона бездиска (`diskless_image.master_machine_id`).
  Отказ без поручения: `diskless` (место бездиска — «через эталон»), `notApproved`, `unknown` (нет такого номера),
  `current` (у ПК уже эта сборка), `busy` (уже есть незавершённое поручение), `helperTooOld` (помощник старше 1.8.0 —
  ставится вручную, `update-helper-net.ps1`).
- Действие, ПК, сборка и итог — одной строкой в журнал сервера.

### 3.4. API для помощника (G:, `PUT /diskless/v1/machines/{id}/status`)

- В ответе `StatusAccepted` — необязательное `helperUpdate {version, sha256, size, path}`, только для `active`
  поручения этого ПК; без поручения поля нет (старые помощники и проверка провода 1.5.1 — без изменений). `path` —
  относительный: `pxe/v1/files/tools/ClubDisklessHelper-1.8.1.exe`.
- В отчёте `MachineStatus` (1.8.0+) — необязательные `helperBuild` (SHA256 своего exe) и
  `helperUpdate {state, sha256, error}`: `state` — `downloading`, `waiting`, `applying` или `failed`; `error` —
  `downloadFailed`, `hashMismatch`, `swapFailed`, `startFailed` с текстом. Регистрация (`register`) тоже передаёт
  `helperBuild`.
- Сервер пишет `machines.helper_build` из отчёта G: и регистрации; `helperUpdate` — в поручение (`progress`, `error`).
- `docs/diskless-api.yaml` — новые поля и абзац про желаемую сборку.

### 3.5. Панель

- Экран ПК, новая карточка «Обновление помощника»:
  - список сборок из `tools`: версия, размер, начало SHA256;
  - выбрать сборку, ПК — номера (`22`, `11-20, 25`, как у зон) или «все гибриды» → «Запустить»; ответ — сколько
    поставлено в очередь и кому отказано с причиной;
  - состояние очереди: активные, в очереди, на паузе, готово, ошибки; «Продолжить», «Отменить».
- Столбец «Помощник»: версия, начало SHA256 сборки и состояние поручения («в очереди», «скачивает», «ждёт конца
  сеанса», «перезапуск», «готово», «ошибка: …»); у мест бездиска — «через эталон».
- API: `GET /panel/api/v1/helper/builds`, `GET/POST /panel/api/v1/helper/updates`,
  `POST /panel/api/v1/helper/updates/resume`, `POST /panel/api/v1/helper/updates/cancel`,
  `POST /panel/api/v1/helper/updates/{id}/cancel`; в `MachineView` — `helperBuild`, `helperUpdate`.
- Тексты — ru, uz (латиница), en.

## 4. Помощник на ПК (Club.Helper 1.8.0)

### 4.1. Сборка и запуск

- При старте помощник один раз считает SHA256 своего exe (`Environment.ProcessPath`) — `helperBuild`.
- При старте проверяет действия Windows при сбое службы и, если их нет или они другие, ставит
  `restart/5000/restart/5000/restart/30000`, сброс счётчика — сутки (как `install-helper.ps1`). Без них замена не
  перезапустит службу.
- Exe и служба те же: `%ProgramFiles%\ClubDiskless\ClubDisklessHelper.exe`, служба `ClubDisklessHelper`, путь в
  ImagePath не меняется.

### 4.2. Загрузка

- Поручение из ответа на отчёт G: принимается, если `path` строго `pxe/v1/files/tools/ClubDisklessHelper-X.Y.Z.exe`,
  SHA256 — 64 hex, размер — до 300 МБ, и сборка не своя. Иначе — `failed`/`downloadFailed`, файл не качается.
- Скачивание — в фоне, не в такте G: (отчёты не прерываются), клиентом для больших файлов, по адресу сервера из
  `helper.json` (HTTPS, сертификат клуба), в `%ProgramFiles%\ClubDiskless\ClubDisklessHelper.exe.new` (права папки,
  тот же диск). Не больше `size` байт; SHA256 считается по ходу; не совпал — файл стирается, `hashMismatch`.
- Сборка, по которой уже была ошибка, повторно не качается до перезапуска службы или другого поручения.

### 4.3. Замена

- Только когда помощник свободен: нет выданных сохранений игрока (сеанс шелла), не выполняется команда канала, на этом
  ПК не открыта правка библиотеки (мастер-том G:/H:). Пока занят — `waiting` («ждёт конца сеанса»).
- Шаги: канал перестаёт принимать команды → запись `%ProgramData%\ClubDiskless\update.json`
  `{fromSha, toSha, toVersion, attempts: 0, startedAt}` → `ClubDisklessHelper.exe` → `.old` → `.new` →
  `ClubDisklessHelper.exe` (повтор до 5 раз через 1 с: файл может держать антивирус; неудача — имена обратно,
  `swapFailed`, канал снова работает) → `applying` в отчёт → выход с кодом не 0. Windows через 5 с запускает службу.
- Два процесса помощника одновременно не работают: новый стартует, когда старый вышел.

### 4.4. Подтверждение и откат

- Новая версия при старте читает `update.json`:
  - своя сборка = `toSha`: попытка +1. Первый принятый сервером отчёт G: — здорова: удалить `.old` и `update.json`,
    в отчёте — новый `helperBuild` (сервер ставит «готово»).
  - попытка больше 3 (три запуска подряд падали до принятого отчёта): `ClubDisklessHelper.exe` → `.failed`, `.old` →
    `ClubDisklessHelper.exe`, в `update.json` — итог `startFailed`, выход с кодом не 0 → Windows запускает прежнюю.
  - своя сборка = `fromSha` (откат или замена не случилась): сообщить итог из `update.json` (`helperUpdate` с
    `failed`), удалить `update.json`, `.new`, `.failed`.
  - сборка ни та ни другая (поставили вручную другую): `update.json` и хвосты удаляются.
- Сервер недоступен — новая версия работает и ждёт; откат только при падениях.
- Хвосты (`.new`, `.old`, `.failed`, `update.json`) удаляются и при старте без поручения; `seal-golden.ps1` и
  `seal-hybrid.ps1` удаляют их перед захватом образа.

### 4.5. Прочее

- `ping` канала отвечает и сборкой (`build`).
- Журнал «Приложение»: одна строка на каждый шаг (скачано, ждёт, замена, подтверждено, откат) с версиями и SHA256.

## 5. Скрипты (наши, `scripts/`)

- `scripts/shell/shell-preflight.ps1`, `shell-install.ps1`, `shell-uninstall.ps1`: вместо списка SHA256 — exe службы
  `ClubDisklessHelper` в `%ProgramFiles%\ClubDiskless`, версия файла не ниже 1.6.0. Новые сборки FAIL не дают.
- `install-helper.ps1`, `update-helper-net.ps1` — ставят 1.8.0 (закреплённый SHA256) и при установке удаляют хвосты
  самообновления; дальше — ручная установка одной сборки, как сейчас.
- `seal-golden.ps1`, `seal-hybrid.ps1` — хвосты самообновления в списки удаляемого.

## 6. Ошибки и крайние случаи

| Случай | Что происходит |
|---|---|
| Хэш не совпал, сборка оборвалась | `.new` стёрт, `hashMismatch`/`downloadFailed`, очередь на паузе |
| Антивирус держит файл при замене | 5 повторов; не вышло — имена обратно, `swapFailed`, служба работает дальше |
| Новая версия падает при старте | после 3 запусков — прежняя, `startFailed`, очередь на паузе |
| Новая версия не доходит даже до чтения `update.json` | отката нет, Windows перезапускает её снова; поэтому каждая сборка сначала проходит PC-22, и очередь на 3 ПК |
| ПК выключили во время скачивания | поручение возвращается в очередь через 10 минут; `.new` стирается при старте |
| ПК выключили между заменой и перезапуском | при загрузке стартует новая версия, дальше как обычно |
| Сеанс игрока длится часами | `waiting`, место в трёх активных занято; администратор видит это в панели |
| Файл сборки в `tools` заменили | активные поручения — `buildChanged`, новое поручение берёт новый SHA256 |
| Гибрид перезалили (h1e с 1.6.0) | `helperTooOld`; ставится вручную `update-helper-net.ps1` |
| Место бездиска | кнопки нет: «через эталон» |

## 7. Проверка

- **Сервер** (`tests/Club.Server.Tests`): сборки и SHA256; очередь (3 активных, выключенный ПК не держит место,
  возврат через 10 минут, пауза на ошибке, продолжить, отменить); кому можно; поле в ответе только для активного
  поручения; провод 1.5.1 без изменений; `done` по `helperBuild`; панель.
- **Помощник** (`tests/Club.Helper.Tests`, подделка файлов и выхода): проверка поручения и пути, загрузка и хэш, ожидание
  свободного момента, замена и её откат при ошибке, подтверждение, откат после 3 падений, итог прежней версии, хвосты.
- Тестовые проекты — по одному (машина разработки).
- **На PC-22:** 1.8.0 вручную → из панели пробная 1.8.1 (только номер версии) → «готово», G:/H: на месте → пробная
  1.8.2, которая падает при старте (собирается только для проверки, константа сборки) → откат на 1.8.1, «ошибка»,
  очередь на паузе. Проверить запуск службы через 5 с после выхода (события 7031/7034) и что откат стирает лишнее.

## 8. Выкатка (каждый шаг — после ОК владельца)

1. Сервер клуба (миграция, панель).
2. PC-22: 1.8.0 вручную, проверка из п. 7.
3. Остальные гибриды: `update-helper-net.ps1` с 1.8.0 — последний ручной обход; скрипты шелла — `publish-kit.sh`.
4. Бездиск: сеанс мастера — 1.8.0 (вручную или кнопкой, если мастер уже на 1.8.0), `seal-golden`, публикация.
5. Образ гибрида для перезаливок с 1.8.0 (h1f) — `patch-hybrid-wim.sh`.

## 9. Не входит в v1

Автоматическое обновление без кнопки; расписание; подпись exe сертификатом; временное обновление обычных мест бездиска;
обновление самого `install-helper.ps1` на ПК; загрузка сборок через панель (кладёт администратор в `tools`).
