# Образы Windows и перезаливка по PXE

Один `install.wim` из золотого образа — для сетевой заливки (WinPE по PXE + DISM). Перезаливка только ручная, из
панели. Хранятся две версии образа: текущая и откатная. PXE используется **только** для перезаливки: каждый день ПК
грузятся со своего диска, упавший PXE-сервер клуб не останавливает.

## Как это работает

```
Панель «Перезалить» ─► задание (reimage_jobs, pxe_armed) ─► класс club-reimage в резервации Kea
ПК перезагружается ─► прошивка UEFI: DHCP ─► Kea: ipxe-shim.efi (TFTP)   ← только машине с флагом
                    ─► shim (подписан Microsoft) ─► ipxe.efi (подписан iPXE)
                    ─► iPXE: DHCP ─► Kea: http://сервер/pxe/v1/boot.ipxe
                    ─► /pxe/v1/machines/<MAC>/boot.ipxe ─► wimboot (подписан Microsoft) + WinPE (boot.wim)
                       + club-deploy.ps1, winpeshl.ini, clubdeploy.json (подкладывает wimboot)
WinPE ─► POST /deploy/v1/start (MAC, диски) ─► план сервера: какой диск, какой образ, имя ПК
      ─► разметка ─► скачивание WIM на временный раздел (докачка) ─► sha256 ─► dism /Apply-Image
      ─► unattend (имя ПК поверх unattend от sysprep) + image.json ─► bcdboot
      ─► POST complete: сервер снимает флаг и убирает класс из Kea ─► только теперь перезагрузка
Windows ─► помощник сообщает imageVersion ─► задание «перезалит»
```

Остальные ПК получают от Kea адрес без имени загрузочного файла — прошивка сразу переходит к диску.

### PXE-флаг и главная гарантия

Флаг — класс `club-reimage` в резервации машины в Kea (`hosts.dhcp4_client_classes`). Сервер снимает его **только
после успешного bcdboot**, и WinPE перезагружается, только когда сервер подтвердил, что Kea уже не отдаст
загрузчик. Сбой на любом шаге → машина остаётся в PXE и при следующей перезагрузке снова попадает в WinPE,
попытка начинается с нуля. «Застряла в PXE» — безопасное состояние; мёртвого загрузчика получиться не может.

Отменить перезаливку можно, только пока WinPE не тронул диск (`diskTouched`). Потом — только довести до конца
или запустить заново (например, откатной версией): новое задание вытесняет упавшее и наследует `diskTouched`,
так что флаг и после этого не снять отменой.

### Secure Boot

Вся цепочка подписана (подробно и с проверкой подписей — `docs/research/secure-boot-pxe.md`): shim iPXE — Microsoft
UEFI CA 2011, `ipxe.efi` — iPXE Secure Boot CA (ему доверяет shim), wimboot — Microsoft (CA 2011 и 2023), WinPE —
Microsoft. Работает и с выключенным Secure Boot. `ipxe.efi` из пакета Ubuntu **не подписан** — его не ставить.

Помощник сообщает о Secure Boot на ПК (включён; есть ли в db сторонний CA 2011 и CA 2023; отозван ли в dbx PCA
2011). Сервер отказывает заранее, если загрузка всё равно не пройдёт, с понятной причиной в панели:

| Причина | Что сделать |
|---|---|
| `bootFilesMissing` | Установить файлы (ниже) |
| `secureBootThirdPartyCa` | В настройках платы включить «Microsoft 3rd-party UEFI CA» (или выключить Secure Boot на время перезаливки) |
| `bootFilesNotSigned` | Файлы на сервере без нужной подписи — поставить скриптом |
| `needsCa2023BootManager` | ПК отозвал старый загрузчик Windows — положить `boot/bootx64.efi` с подписью Windows UEFI CA 2023 |

ПК с отозванным PCA 2011 автоматически получают загрузчик CA 2023; остальные — загрузчик из boot.wim.

Почему класс, а не имя файла в резервации: проверено на настоящей Kea 3.0.3 — имя файла из резервации
перекрывает классы, и iPXE получал бы `ipxe.efi` снова, по кругу. Классы из резервации видят только
«дополнительные» классы (`only-in-additional-list` + `evaluate-additional-classes` в подсети) — так и сделано.

### Какой диск стирается

План даёт сервер (`TargetDisk.Choose`), WinPE перед стиранием сверяет номер, серийный номер и размер.

- Только внутренние шины: NVMe, SATA, SAS, RAID, ATA, SCSI. USB, iSCSI, SD, виртуальные — никогда.
- Помощник сообщает системный диск (с которого грузится Windows). Если он известен — стирается только диск с
  этим серийным номером. Нет такого диска (заменили SSD) — отказ, пока администратор не запустит перезаливку
  с «разрешить новый диск».
- Если системный диск неизвестен — только единственный подходящий по размеру. Несколько — отказ.
- Размер: EFI + MSR + распакованный образ с запасом 15 % + сам WIM (временный раздел) + 4 ГиБ, не меньше 64 ГиБ.

Разметка (только UEFI/GPT): EFI 260 МБ FAT32, MSR 16 МБ, Windows NTFS, временный раздел под WIM в конце диска.
После применения временный раздел удаляется, Windows расширяется на весь диск. Раздел восстановления (WinRE)
не создаётся. BIOS/Legacy — отказ `biosNotSupported`.

### Личность машины

Образ одинаков для всех. При заливке WinPE получает от сервера имя компьютера (из имени места, NetBIOS до 15
символов) и дописывает его в `Windows\Panther\unattend.xml` (проход specialize) поверх unattend, который положил
sysprep: настройки OOBE золотого образа сохраняются. Рядом — `ProgramData\ClubDiskless\image.json` с версией
образа; помощник сообщает её серверу.

Образ **обязан** быть генерализован (`sysprep /generalize`): иначе у всех ПК один MachineGUID, и античит свяжет
машины. WinPE проверяет `SYSTEM\Setup\Status\SysprepStatus\GeneralizationState` в залитом реестре; значение
не 7 — отказ `notGeneralized`, образ помечается в панели. [ГИПОТЕЗА: значение 7 проверить на стенде.]

## Установка на сервере (от root)

Каталоги и настройки сервера клуба:

```json
"Imaging": {
  "Enabled": true,
  "Root": "/srv/club/images",
  "PxeRoot": "/srv/club/pxe",
  "PublicBaseUrl": "http://192.168.77.1:5080"
}
```

`PublicBaseUrl` — адрес сервера для ПК по **HTTP** (iPXE и WinPE): сервер должен слушать этот адрес в сети клуба.
`Root/incoming/` — сюда кладётся `install.wim` (scp или SMB); `Root` может быть смонтированным датасетом TrueNAS.

TFTP и подписанная цепочка (iPXE v2.0.0 и wimboot v2.9.0 из официальных релизов, sha256 закреплены в скрипте):

```bash
apt install -y tftpd-hpa
sudo scripts/pxe/install-boot-files.sh
```

Скрипт кладёт в `/srv/tftp` `ipxe-shim.efi`, `ipxe.efi` (подписанный, из `x86_64-sb`) и `undionly.kpxe`, в
`/srv/club/pxe` — `wimboot` (каталоги меняются `TFTP_ROOT`/`PXE_ROOT`; `Imaging:TftpRoot` должен совпадать).
Пакет Ubuntu `ipxe` не нужен: его `ipxe.efi` не подписан.

WinPE: собрать на Windows-машине с ADK скриптом `scripts/winpe/build-winpe.cmd`, содержимое `out\pxe`
скопировать в `PxeRoot`:

```
/srv/club/pxe/wimboot            ← install-boot-files.sh
/srv/club/pxe/boot/BCD
/srv/club/pxe/boot/boot.sdi
/srv/club/pxe/boot/bootx64.efi   ← загрузчик с подписью Windows UEFI CA 2023 (необязателен)
/srv/club/pxe/sources/boot.wim
```

Всё видно в панели: «Образы Windows» → «Файлы загрузки по сети» — есть ли файл, кем подписан, цела ли подпись,
версия.

Скрипт заливки, `winpeshl.ini` и `clubdeploy.json` (адрес сервера) в `boot.wim` не зашиваются — wimboot берёт их
с сервера при каждой загрузке, поэтому обновление сервера обновляет и заливку.

Kea: после включения образов заново скачать `kea-dhcp4.conf` на экране «Сеть» и установить (`docs/network.md`) —
в нём появятся классы `club-reimage-*`.

Прошивка каждого ПК: UEFI, сетевая загрузка IPv4 включена и стоит **первой** в порядке загрузки. ПК без флага
получает адрес без загрузчика и через несколько секунд грузится с диска. [ГИПОТЕЗА: задержка зависит от платы —
замерить на стенде.]

## Образ: сборка и публикация

1. Золотой ПК: установка Windows → audit mode (Ctrl+Shift+F3 на OOBE) → весь софт, помощник бездиска
   (`docs/helper.md`) → `sysprep /generalize /oobe /shutdown /unattend:<ваш unattend>`.
2. Загрузиться в WinPE/с USB и снять образ: `dism /Capture-Image /ImageFile:D:\install.wim /CaptureDir:C:\ /Name:"Club" /Compress:max`.
3. Положить `install.wim` в `incoming/` на сервере. На экране «Образы Windows» — «Импортировать» с меткой
   версии (`win11-2609`) и индексом образа внутри WIM. Сервер переносит файл, читает состав WIM, считает sha256.
4. «Опубликовать»: версия становится текущей, прежняя текущая — откатной, более старая удаляется (когда её не
   использует ни одна незавершённая перезаливка). «Откатить» меняет текущую и откатную местами.

Импорт переживает падение сервера на любом шаге (перенос через `.partial`, повтор с начала шага).

## Перезаливка

«Рабочие станции» → «Перезалить» (текущая или откатная версия) → перезагрузить ПК. Ход виден в строке машины:
ждёт загрузки по сети → разметка → скачивание (проценты) → проверка → распаковка → имя ПК → загрузчик → первая
загрузка Windows → перезалит. Сбой показывает этап и причину; ПК на экране WinPE ждёт Enter (без перезагрузок
по кругу). Сервер не перезагружает ПК сам.

## Известные ограничения и открытые вопросы

- **Secure Boot** — подписанная цепочка сделана, но на железе не проверялась; shim подписан только CA 2011,
  поэтому ПК без стороннего CA Microsoft в db (часть ноутбуков и Secured-core) без изменения настроек платы не
  загрузятся по сети — сервер скажет об этом заранее.
- Образ скачивается по HTTP без авторизации: во время перезаливки его может скачать любой в сети клуба, подделав
  MAC. В образе — ключ клуба помощника (`helper.json`); с ним можно только зарегистрировать машину, которую потом
  одобряет администратор.
- USB-обёртка того же WIM, активация Windows (OEM/MAK/KMS), раздел восстановления — не сделаны.
- WinPE-часть проверена только в PowerShell 7 на Linux с заглушками команд Windows (`DeployScriptTests`):
  API, скачивание с докачкой, sha256, порядок шагов, сбой и повтор. Командлеты дисков, dism, bcdboot, wimboot и
  прошивки — только на стенде.

## Проверка на стенде

1. Собрать WinPE, положить файлы, включить `Imaging`, обновить конфиг Kea; `curl http://<сервер>/pxe/v1/boot.ipxe`.
2. ПК с Secure Boot off, сеть первой: без флага — грузится с диска (засечь задержку).
2a. ПК с Secure Boot **on**: перезаливка проходит (shim → iPXE → wimboot → WinPE); ПК с отключённым сторонним CA —
    в панели отказ `secureBootThirdPartyCa`; ПК с применённым отзывом PCA 2011 — грузится загрузчиком CA 2023.
3. «Перезалить» → перезагрузка → WinPE → заливка → Windows с именем места; в панели «перезалит».
4. Выдернуть сеть во время скачивания → докачка после возврата. Выключить ПК во время dism → после включения
   снова WinPE, заливка с нуля.
5. ПК с двумя дисками и флешкой — стёрт только системный; `diskChanged`/`systemDiskNotFound` при подмене диска.
6. Образ без sysprep → `notGeneralized`; `GeneralizationState` в образе до/после sysprep.
7. FACEIT/Vanguard на перезалитом ПК; уникальность MachineGUID на двух ПК (`reg query HKLM\SOFTWARE\Microsoft\Cryptography /v MachineGuid`).
8. Q5: время заливки WIM 20+ ГБ по сети на 1 и 10 ПК одновременно.
