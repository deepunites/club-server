# Полный бездиск и профили игроков (проект)

Статус: проект, 2026-10-10. Цель — открытие клуба в начале ноября 2026: 65 ПК, из них 28 — полный бездиск
(зоны 1–2), 35 — гибрид (зоны 3–5 и 10 новых ПК). Сравнение с ggRock — переписка 2026-10-06; главное взято оттуда:
личный слой записи на каждый ПК, сброс при перезагрузке, версии образа через «применить».

## 1. Что получает клуб

| | Бездиск (зоны 1–2) | Гибрид (остальные) |
|---|---|---|
| Windows | по сети, личный диск места, чистый после каждой загрузки | локально на ПК |
| Игры | по сети, личный слой записи места, чистый после загрузки | так же |
| Обновление Windows | один раз в эталоне → «Опубликовать» | перезаливка по PXE (`docs/imaging.md`) |
| Сохранения игрока | профиль игрока с сервера при входе в шелл (раздел 7) | так же |
| Сервер упал | бездисковые ПК встают | Windows работает, игр нет |

Античит: FACEIT и Valorant (Vanguard) — только в гибридных зонах (решение клуба, 2026-10-10); на бездисковых ПК
игр с античитами уровня ядра нет, **Secure Boot на них выключен** — обычный iPXE, без подписанной цепочки.

## 2. Хранение (TrueNAS, ZFS)

```
ssd/club/diskless/images/win11            эталон Windows (zvol), версии — снимки @v-<метка>
ssd/club/diskless/seats/seat-07-sys       клон снимка эталона: личный системный диск места 7
ssd/club/diskless/seats/seat-07-sys@clean снимок сразу после клонирования — к нему откат перед загрузкой
ssd/club/lib                              мастер библиотеки игр (как сейчас)
ssd/club/published/lib-<версия>           снимок/клон версии библиотеки (как сейчас)
ssd/club/seats/games-seat-07              клон версии библиотеки: личный слой игр места 7 (@clean — то же)
hdd/club/lib2 …                           вторая библиотека (одиночные игры, диск H:) — этап 3
```

- Личный диск места — **записываемый клон** (ZFS copy-on-write): занимает место только под записанное.
- **Сброс** перед каждой загрузкой — `pool.snapshot.rollback` к `@clean`: мгновенно и **без изменения настроек iSCSI**
  (таргет, экстент, LUN те же). Откат выполняется, только когда у таргета места нет сессии.
- **Новая версия** эталона или библиотеки доходит до места при его загрузке: клон пересоздаётся от нового снимка
  (экстент меняется — перезагрузка конфигурации iSCSI, с проверкой видимости, как при публикации сейчас).
- **Ни одного read-only экстента.** Ошибка TrueNAS 25.10 (copy manager SCST и read-only устройства, исправлена в
  TrueNAS 27, релиз — декабрь 2026) срабатывает только при read-only устройствах; личные клоны записываемые, значит,
  ошибки нет. Это же решает запись лаунчеров (Steam, Battle.net) в папки игр: запись идёт в личный слой и
  сбрасывается при перезагрузке.
- Гибридные ПК переходят на тот же личный слой игр (клон на место) вместо общего read-only тома.

Объёмы (ориентир ggRock): 10 ГБ личного слоя на ПК (система + игры), 15 % пула свободно. Для клуба:
эталон ~60 ГБ + игры на SSD + 65 × 10 ГБ ≈ игры + 0,7 ТБ. ОЗУ сервера 64 ГБ: кэш ZFS (ARC) ограничить ~40 ГБ,
остальное — ВМ сервера клуба и TrueNAS.

Личный слой игр сделан (2026-10-10, `Library:PersonalGames`, помощник 1.5.0): `SeatGames` на сервере,
таргет `games-seat-NN`, CHAP и группа места (IQN Windows ПК; у бездискового — ещё IQN места из iBFT). Точка сброса —
запрос назначения при старте помощника (`GET …/volume`): нет сессии (или помощник сообщил `attached=false` — сессия
осталась от прошлой загрузки) → откат к `@clean`, новая версия → клон пересоздаётся. Пока ПК работает, назначение
не меняется. Публикация в этом режиме — только снапшот мастера; удаление старой версии — снапшот с defer, он уходит,
когда последнее место пересоздало клон. Сбой сборки диска места — отчёты повторяют её не чаще раза в 2 минуты.

## 3. iSCSI и доступ

На каждое бездисковое место — таргеты `seat-NN-sys` и `seat-NN-games`, на гибридное — `seat-NN-games`:

- группа инициаторов места: только IQN этого места (`iqn.2026-10.local.club:seat-07`), CHAP на место (секрет
  генерирует сервер, ПК получает его в скрипте iPXE по HTTPS-запросу от своего MAC — см. риски);
- имя инициатора бездискового ПК задаёт iPXE (`set initiator-iqn`), Windows берёт его из iBFT;
- таргеты создаются один раз при включении места; дальше — только откаты.

## 4. Загрузка бездискового ПК

```
Прошивка UEFI (сеть первой) ─► DHCP Kea: класс club-diskless в резервации места → ipxe-shim.efi (TFTP)
  ─► ipxe.efi ─► DHCP ─► http://сервер/pxe/v1/boot.ipxe ─► /pxe/v1/machines/<MAC>/boot.ipxe
Сервер: место бездисковое → нет сессии на seat-NN-sys → откат/пересоздание клона (если новая версия) → скрипт:
  set initiator-iqn iqn.2026-10.local.club:seat-07
  sanboot iscsi:<портал>::::<iqn таргета seat-07-sys>      (CHAP — username/password в скрипте)
Windows (iBFT) грузится с личного диска; помощник подключает seat-07-games как G: (как в гибриде).
```

- Класс `club-diskless` держится в резервации всегда (в отличие от `club-reimage`, который снимается после
  заливки). Флаг «бездиск» — у машины в «Рабочих станциях».
- Сервер не ответил (упал, перезапускается): первый скрипт `/pxe/v1/boot.ipxe` повторяет запрос 12 раз по 5 с,
  потом — локальная загрузка (у гибридного ПК); скрипты места (ожидание, сбой, повтор после неудачного sanboot)
  повторяют запрос без конца, циклом `goto` с `chain --replace` — стек iPXE не растёт. Каждый `sanhook`/`sanboot`
  предваряется `sanunhook --drive 0x80 ||`: диск, подключённый неудачной попыткой, не занимает номер.
- Диск работающего места не трогается: если к его таргету есть сессия с другого адреса, чем запрос iPXE (адрес boot.ipxe
  открыт, MAC виден в сети), ответ — «подождите»; с того же адреса (ПК выключили кнопкой, сессия висит) — сброс.

## 5. Эталон Windows для бездиска

- Windows 11 (обход проверки процессора для Ryzen 5 1600), установка **сразу на iSCSI**: iPXE `sanhook` эталонного
  zvol + установщик Windows через wimboot; установщик видит диск по iBFT.
- В эталоне — драйверы всех сетевых карт зон 1–2 (Realtek/Intel), видеодрайверы NVIDIA и AMD, шелл, помощник.
- Выключены: Windows Update (обновления — только в режиме мастера), дефрагментация, гибернация, быстрый запуск;
  файл подкачки — небольшой, на личном диске. Энергосбережение сетевой карты — выключено (иначе отвал диска).
- **Режим мастера** (как мастер-том библиотеки): одно место грузится с записываемым клоном без сброса, админ
  ставит обновления и программы, выключает ПК → «Опубликовать»: снимок клона становится новой версией эталона
  (цепочка клонов ZFS; старые версии удаляются с `zfs promote`, когда на них не опирается ни одно место).
  Откат версии — как у библиотеки.
- Активация: цифровая лицензия по железу каждого ПК (у ПК с ранее активированной Windows) или KMS клуба.

## 6. Kea, панель, помощник

- Kea: класс `club-diskless` (тот же механизм, что `club-reimage`; оба — `only-in-additional-list`).
- Панель «Рабочие станции»: режим места «бездиск / гибрид», версия эталона, режим мастера, сброс диска места.
- Помощник: назначение тома без `ReadOnly` (личный слой); проверка «только чтение» остаётся для общего тома
  (переходный период). Помощник ставится в эталон бездиска так же, как в гибридный образ.

## 7. Профили игроков (сохранения, вход в лаунчеры)

Задача: игрок входит в шелл на любом ПК клуба — у него его сохранения, настройки игр и (по желанию) вход в Steam.

```
Шелл (вход игрока, ID игрока) ─► помощник на ПК (локальный канал \\.\pipe\club-diskless-helper)
  ─► сервер: выдать профиль игрока ─► помощник раскладывает файлы в профиль Windows игрока
Шелл (выход / конец сеанса) ─► помощник: собрать файлы по правилам ─► сервер: сохранить новую версию
```

- Сервер хранит профиль как архив версий (`profiles/<ID игрока>/<время>.zip`, последние 5), лимит на игрока
  (1–2 ГБ), архивы зашифрованы ключом клуба (AES-GCM): в них токены входа в лаунчеры. ID игрока — непрозрачная
  строка от шелла; кто такой игрок, сервер не знает.
- Правила путей — в панели: общий список (`%USERPROFILE%\Saved Games`, `Documents\My Games`, `%APPDATA%\…`,
  папки отдельных игр на G:/H:) и правила лаунчеров. Пути внутри личного слоя игр сохраняются так же.
- Один игрок — один ПК: сервер выдаёт профиль только одному ПК; повторный вход на другом ПК — после выхода на
  первом (или с последней сохранённой версией, если первый ПК пропал). Помощник сохраняет профиль и в середине
  сеанса (раз в 10 минут) — на случай выключения ПК.
- Steam: сохранения большинства игр Steam синхронизирует сам (Steam Cloud). «Запомнить вход» — файлы Steam
  (`config\loginusers.vdf`, `config\config.vdf`, `%LOCALAPPDATA%\Steam\local.vdf`) в профиле игрока **только по
  согласию игрока** (флаг от шелла). [ГИПОТЕЗА: токен Steam зашифрован DPAPI; на бездисковых ПК одна и та же
  Windows — токен, вероятно, переносится между ПК; на гибридных у каждого ПК своя Windows — вероятно, Steam
  попросит войти заново. Проверить на стенде.]
- Шеллу нужно: при входе — вызвать «профиль игрока X» (ID, SID пользователя Windows, флаг Steam); при выходе —
  «сохранить профиль» и дождаться ответа до выхода из сеанса (`club-contracts/docs/SHELL_CHANGES.md`, п. 23).

## 9. Риски

- iSCSI-загрузка Windows 11 по iBFT на клиентской редакции — проверить на стенде первым делом. Secure Boot на
  бездисковых ПК выключен (FACEIT там нет), подписанная цепочка shim → iPXE не нужна.
- Отвал сети = синий экран бездискового ПК: энергосбережение сетевой карты выкл., кабели и коммутаторы проверены,
  сервер на ИБП.
- Разное железо в одном эталоне (Intel H410/H510 и AMD A520, NVIDIA и AMD): драйверы всех в эталоне; при сбое —
  отдельный эталон на платформу.
- Одновременная загрузка 28 ПК: каналы 1 Гбит/с у ПК, 10 Гбит/с у сервера и между коммутаторами; ОЗУ под кэш.
- CHAP-секрет места в скрипте iPXE: скрипт выдаётся по MAC, MAC подделывается. Компромисс как у всех бездисков
  (ggRock, CCBoot); защита — отдельная сеть клуба без гостевых устройств.
