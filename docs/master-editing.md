# Мастер-том: правка игр (режим суперклиента)

Версии библиотеки — снимки мастер-тома (`Library:MasterZvol`). Чтобы обновить игры, администратор открывает мастер-том
**на запись одному ПК** — суперклиенту — и работает с ним как с обычным диском `M:`: ставит, обновляет, удаляет игры
в их лаунчерах. Потом «Закончить правку» и «Опубликовать»: снимок станет новой версией для всех ПК.

Остальные ПК мастер-том не видят; игроки по-прежнему получают только опубликованные версии и только для чтения.

## Как это работает

```
Панель «Открыть для правки на ПК X»
  └─ сервер (операция masterOpen в журнале хранилища, шаги идемпотентны):
       CHAP (новый секрет, 16 символов) → группа инициаторов = [IQN ПК X] → экстент мастер-тома на запись
       → таргет club-master (CHAP + эта группа) → LUN → проверка: SendTargets от имени IQN ПК X (discovery без
       CHAP); не виден — конфигурация iSCSI применяется заново (как у публикации, но без провала операции:
       том открыт с оговоркой, панель показывает её в карточке мастер-тома)
  └─ помощник на ПК X получает в ответе на отчёт { targetIqn, portal, chapUser, chapSecret, driveLetter }
       → вход в таргет с CHAP → диск на запись → online → буква M:
Панель «Закончить правку»
  └─ сервер перестаёт отдавать назначение (операция masterClose ждёт)
  └─ помощник: Write-VolumeCache M → диск offline → отключение таргета
  └─ сервер: таргет (без force: пока ПК подключён — ждём, попытки не тратятся) → экстент → группа → CHAP
Панель «Опубликовать»
```

## Гарантии

- **Доступ только одному ПК**: группа инициаторов из одного IQN **и** CHAP с секретом, новым на каждое открытие.
  IQN можно подделать, секрет — нет: его знает только помощник этого ПК (приходит по авторизованному API бездиска).
- **Порядок в TrueNAS** учитывает её ловушки (`docs/research/truenas-api.md` §8.3): пустая группа инициаторов открывает
  таргет всем — группа создаётся с IQN и никогда не пустеет; при удалении группы TrueNAS обнуляет ссылку таргета
  (таргет открыт всем) — поэтому сначала удаляется таргет, потом группа и CHAP. Проверено тестом по журналу вызовов.
- **Публикация запрещена**, пока мастер-том не закрыт (`masterOpen`): снимок посреди правки мог бы поймать
  недописанную NTFS. Открыть мастер-том нельзя, пока идёт публикация (`publishPending`).
- **Закрытие ждёт ПК**: таргет удаляется без force — TrueNAS не даст удалить его, пока есть сессия. Если на `M:`
  открыты файлы и диск не уходит offline, помощник не отключается и сообщает ошибку; сервер ждёт.
- **Принудительное отключение** (ПК выключился или завис) рвёт сессию. NTFS мастер-тома могла остаться
  недописанной: пометка `dirty`, публикация — только с явным подтверждением. Чистое открытие и закрытие снимает
  пометку (Windows проверяет том при подключении на запись).
- Назначение мастер-тома у помощника только в памяти: после перезагрузки без сервера том не подключается; без
  ответа сервера помощник уже подключённый том не трогает.
- Библиотечные тома помощник отличает по `:games-` в имени таргета; `club-master` он не отключает при смене версии.
- Отметка «M:» у ПК в списке рабочих станций — отчёт помощника. Отчёт без мастер-тома (помощник 1.4+ шлёт его, когда
  мастер-том не назначен и не подключён) её снимает, закрытие мастер-тома — тоже: «none» помощник присылает один раз,
  и если этот отчёт потерялся или сессию оборвали без него, прежний «mounted» иначе остался бы навсегда.

## Требования

- Помощник 1.4.1+ на ПК администратора: он сообщает IQN инициатора (`Get-InitiatorPort`), а перед чтением сам
  включает и запускает службу «Инициатор iSCSI Майкрософт» (MSiSCSI). Без IQN ПК нет в списке. На 1.4.0 — один раз
  `Set-Service MSiSCSI -StartupType Automatic; Start-Service MSiSCSI; Restart-Service ClubDisklessHelper`.
- API бездиска по **HTTPS** (`HelperOptions.CaCertificatePath`): секрет CHAP приходит в ответе сервера.
- Права сервисного пользователя TrueNAS: плюс `SHARING_ISCSI_AUTH_*` и `SHARING_ISCSI_INITIATOR_*` (или
  `SHARING_ISCSI_WRITE`, который включает все iSCSI `*_WRITE`).

## Настройки (`Library`)

| Ключ | По умолчанию | |
|---|---|---|
| `MasterTargetName` | `club-master` | имя таргета (без `games-`) |
| `MasterExtentName` | `clubsrv-master` | экстент мастер-тома на запись |
| `MasterDriveLetter` | `M` | буква на ПК суперклиента |

## Проверено и не проверено

- Проверено тестами: поддельный TrueNAS с правилами настоящего (секрет 12..16, CHAP-тег в использовании не
  удаляется, удаление группы открывает таргет всем), сервер и помощник на поддельной Windows — полный цикл открыть →
  M: на запись → закончить → сброс и отключение → закрыто; принудительное закрытие; повторное открытие с новым
  секретом; отказы; IQN, появившийся после старта помощника, доходит до сервера без перезапуска помощника.
- Проверено на стенде (2026-10-02, Windows 11, помощник 1.4.0): `Get-InitiatorPort … ConnectionType -eq 'iSCSI'`
  даёт IQN Microsoft-инициатора, но только при запущенной службе MSiSCSI. В Windows она по умолчанию остановлена, а
  помощник запускал её лишь при подключении тома, и на новом стенде IQN не появлялся никогда; к тому же пустой IQN
  запоминался до перезапуска помощника. Исправлено в 1.4.1: служба запускается перед чтением IQN (ожидание до
  10 с), IQN читается коротким опросом со следующего такта после старта (регистрация его не ждёт), пустой IQN
  перечитывается не чаще раза за такт с паузой, растущей до 10 минут (полный опрос фактов не повторяется), пока IQN
  нет — предупреждение в журнале Windows.
- [ГИПОТЕЗА] `Connect-IscsiTarget -AuthenticationType ONEWAYCHAP` с секретом 16 символов; `Write-VolumeCache` +
  `Set-Disk -IsOffline` при открытых файлах отказывает, а не отключает насильно — проверить на стенде.
- [ГИПОТЕЗА] `iscsi.auth.update` принимает частичное обновление `{secret}` (как остальные update в middleware).

## Проверка на стенде

1. Помощник 1.4.1+ на ПК администратора (MSiSCSI можно не трогать — помощник запустит её сам) → в течение ~1 мин он
   в списке «Открыть для правки» (IQN читается со второго такта после старта службы).
2. Открыть → через ~30 с на ПК диск `M:` на запись; с другого ПК вход в `club-master` отклоняется (неверный CHAP
   и чужой IQN). `iscsi.target.query` — группа с одним IQN, `authmethod: CHAP`.
3. Поставить игру на `M:` через лаунчер; «Закончить правку» → `M:` исчезает, в панели «закрыт»; «Опубликовать» → на
   ПК игроков новая версия с этой игрой.
4. Открыть файл на `M:` и нажать «Закончить правку» → помощник сообщает ошибку, том остаётся, сервер ждёт.
5. Выключить ПК суперклиента с открытым томом → «Отключить принудительно» → «закрыт», пометка о недописанности,
   публикация спрашивает подтверждение.
