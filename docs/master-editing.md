# Мастер-том: правка игр (режим суперклиента)

Версии библиотеки — снимки мастер-тома (`Library:MasterZvol`). Чтобы обновить игры, администратор открывает мастер-том
**на запись одному ПК** — суперклиенту — и работает с ним как с обычным диском `M:`: ставит, обновляет, удаляет игры
в их лаунчерах. Потом «Закончить правку» и «Опубликовать»: снимок станет новой версией для всех ПК.

Остальные ПК мастер-том не видят; игроки по-прежнему получают только опубликованные версии и только для чтения.

## Как это работает

```
Панель «Открыть для правки на ПК X»
  └─ сервер (операция masterOpen в журнале хранилища, шаги идемпотентны):
       CHAP (новый секрет, 16 символов) → группа инициаторов = [IQN ПК X] → экстент мастер-тома на запись
       → таргет club-master (CHAP + эта группа) → LUN → проверка: SendTargets от имени IQN ПК X (discovery без
       CHAP); не виден — конфигурация iSCSI применяется заново (как у публикации, но без провала операции:
       том открыт с оговоркой, панель показывает её в карточке мастер-тома)
  └─ помощник на ПК X получает в ответе на отчёт { targetIqn, portal, chapUser, chapSecret, driveLetter }
       → вход в таргет с CHAP → диск на запись → online → буква M:
Панель «Закончить правку»
  └─ сервер перестаёт отдавать назначение (операция masterClose ждёт)
  └─ помощник: Write-VolumeCache M → диск offline → отключение таргета
  └─ сервер: таргет (без force: пока ПК подключён — ждём, попытки не тратятся) → экстент → группа → CHAP
Панель «Опубликовать»
```

## Мастер-том на букве библиотеки (`MasterDriveLetter` = `DriveLetter`)

Лаунчеры (Epic, Battle.net, Ubisoft, Rockstar, Lesta) запоминают путь установки: игра, поставленная на `M:`, на местах
(где библиотека — `G:`) лаунчеру не видна. Поэтому клуб ставит `Library:MasterDriveLetter=G` — ту же букву, что
`Library:DriveLetter` (сравнение без учёта регистра): на ПК правки мастер-том занимает `G:` **вместо** тома библиотеки
(личного диска `games-seat-NN` или общей версии), и лаунчеры записывают пути `G:\…` так, как их видят места.

```
Панель «Открыть для правки на ПК X» (буквы совпадают)
  └─ сервер: ПК X не получает том библиотеки — ни в ответе на отчёт, ни в запросе при старте (GET …/volume → 204);
       в ответе на отчёт рядом с master — libraryLetterReserved: true. Личный диск X не сбрасывается и не удаляется,
       просто не выдаётся. Остальные ПК — как обычно; буквы разные — всё как раньше (поля нет)
  └─ помощник 1.5.1 на X: сначала отпускает том библиотеки, как при обычном отключении — процессы с G: (игра запущена —
       ждём), у личного диска Write-VolumeCache G → offline, отключение только таргета :games- (системный диск
       бездиска, мастер-том и чужие сессии не трогаются); потом вход в club-master → на запись → online → G:
Панель «Закончить правку»
  └─ помощник: сначала мастер-том (Write-VolumeCache G → offline → отключение), в том же такте — личный диск снова на G:
       (тот же диск этой загрузки, без сброса; если X перезагружали во время правки — запросом при старте, со сбросом)
```

- Пока назначение мастер-тома есть, том библиотеки не монтируется **ни из ответа сервера, ни из `assignment.json`, ни
  после 3 минут без сервера** (сохранённый личный диск). Ответ с `libraryLetterReserved` не меняет ни назначение в
  памяти, ни `assignment.json`. Запрос при старте во время правки отвечает 204 с заголовком
  `X-Library-Letter-Reserved: true`: помощник 1.5.1 не монтирует ничего, но и `assignment.json` не затирает (как при
  «нечего монтировать») — если ПК выключат до конца правки, а утром сервер будет недоступен, сохранённый том останется.
- То же **без назначения**, по тому, что на ПК: мастер-том на букве тома библиотеки (служба помощника перезапустилась
  во время правки, а сервер ещё не ответил или недоступен; правку закрыли, а мастер-том не отключился) — том
  библиотеки на эту букву не ставится. В первом такте после запуска службы помощник сначала смотрит мастер-том, потом
  том из `assignment.json`.
- **Том занят** — насильно не отключается, повтор каждый такт: с G: запущена игра или лаунчер держит файлы (Windows не
  переводит диск offline или не завершает сессию). В отчёте том — `switchPending` с причиной `master volume waits: …`,
  мастер-том — `failed` с причиной `drive letter G: is held by the library volume: volume in use (open files on G:): …`
  (в панели — у мастер-тома на экране «Библиотека игр» и в подсказке к отметке мастер-тома у машины). Закрыть игру или
  лаунчер — в течение такта G: переходит к мастер-тому.
- Отпущенный том — не сбой: в панели у ПК правки том «нет» с подсказкой `drive letter G: is given to the master volume
  (library editing)`, в счётчиках библиотеки — «не подключён».
- «Закончить правку» с открытыми на G: файлами: мастер-том, как и раньше, не отключается (сервер ждёт), а личный диск
  на занятую букву не лезет — вернётся в том такте, когда мастер-том отключится.
- **«Отключить принудительно»** (или перезапуск iSCSI в TrueNAS во время закрытия): TrueNAS удаляет таргет и рвёт
  сессию, а Windows её восстанавливает (`IsConnected = false`) — том остаётся на G:. Помощник ждёт 2 минуты (вдруг
  связь вернётся — тогда отключение обычное, со сбросом кэша; мастер-том в отчёте `failed`: `iSCSI session is
  reconnecting …`), потом отключает сессию без сброса кэша (сбрасывать некуда; Windows держит запросы к пропавшему
  таргету не дольше MaxRequestHoldTime, 60 с). На томе открыты файлы — Windows не отключает и такую сессию: `failed` с
  её отказом, повтор каждый такт; закрыть лаунчер — G: возвращается личному диску. Раньше (1.5.0 и буква `M:`) такая
  сессия оставалась до перезагрузки ПК, на `M:` это было безвредно.
- **Нужен помощник 1.5.1 на эталоне.** 1.5.0 пустой ответ сервера считает «диск готовится» и личный диск не отпускает:
  мастер-том падает с `drive letter G is in use`. Обходной путь на 1.5.0 — перезагрузить ПК правки после «Открыть»:
  при старте сервер тома не даёт, G: свободна, мастер-том подключается (при закрытии один такт будет `failed` у тома).
- Ограничение: назначение мастер-тома у помощника только в памяти, на диск не сохраняется (после перезагрузки без
  сервера мастер-том не подключается — так задумано). Если ПК правки **перезагрузили**, а запрос при старте не прошёл
  (сервер ответил ошибкой), мастер-тома на ПК ещё нет и о правке помощник не знает: сохранённая версия общей библиотеки
  встаёт на G: и отпускается в том же такте, когда придёт ответ на первый отчёт; сервер недоступен совсем — ПК
  работает с ней, как место (сохранённый личный диск — только после 3 минут без сервера, как всегда). Перезапуск одной
  службы этим не страдает: мастер-том на ПК, и помощник видит его до того, как тронуть том библиотеки.

## Гарантии

- **Доступ только одному ПК**: группа инициаторов из одного IQN **и** CHAP с секретом, новым на каждое открытие.
  IQN можно подделать, секрет — нет: его знает только помощник этого ПК (приходит по авторизованному API бездиска).
- **Порядок в TrueNAS** учитывает её ловушки (`docs/research/truenas-api.md` §8.3): пустая группа инициаторов открывает
  таргет всем — группа создаётся с IQN и никогда не пустеет; при удалении группы TrueNAS обнуляет ссылку таргета
  (таргет открыт всем) — поэтому сначала удаляется таргет, потом группа и CHAP. Проверено тестом по журналу вызовов.
- **Публикация запрещена**, пока мастер-том не закрыт (`masterOpen`): снимок посреди правки мог бы поймать
  недописанную NTFS. Открыть мастер-том нельзя, пока идёт публикация (`publishPending`).
- **Закрытие ждёт ПК**: таргет удаляется без force — TrueNAS не даст удалить его, пока есть сессия. Если на `M:`
  открыты файлы и диск не уходит offline, помощник не отключается и сообщает ошибку; сервер ждёт.
- **Принудительное отключение** (ПК выключился или завис) рвёт сессию. NTFS мастер-тома могла остаться
  недописанной: пометка `dirty`, публикация — только с явным подтверждением. Чистое открытие и закрытие снимает
  пометку (Windows проверяет том при подключении на запись).
- Назначение мастер-тома у помощника только в памяти: после перезагрузки без сервера том не подключается; без
  ответа сервера помощник уже подключённый том не трогает.
- Библиотечные тома помощник отличает по `:games-` в имени таргета; `club-master` он не отключает при смене версии.
- Отметка «мастер-том M:» (буква — из `Library:MasterDriveLetter`) у ПК в списке рабочих станций — отчёт помощника, в
  подсказке — причина сбоя. Отчёт без мастер-тома (помощник 1.4+ шлёт его, когда
  мастер-том не назначен и не подключён) её снимает, закрытие мастер-тома — тоже: «none» помощник присылает один раз,
  и если этот отчёт потерялся или сессию оборвали без него, прежний «mounted» иначе остался бы навсегда.

## Требования

- Помощник 1.4.1+ на ПК администратора: он сообщает IQN инициатора (`Get-InitiatorPort`), а перед чтением сам
  включает и запускает службу «Инициатор iSCSI Майкрософт» (MSiSCSI). Без IQN ПК нет в списке. На 1.4.0 — один раз
  `Set-Service MSiSCSI -StartupType Automatic; Start-Service MSiSCSI; Restart-Service ClubDisklessHelper`.
- API бездиска по **HTTPS** (`HelperOptions.CaCertificatePath`): секрет CHAP приходит в ответе сервера.
- Права сервисного пользователя TrueNAS: плюс `SHARING_ISCSI_AUTH_*` и `SHARING_ISCSI_INITIATOR_*` (или
  `SHARING_ISCSI_WRITE`, который включает все iSCSI `*_WRITE`).

## Настройки (`Library`)

| Ключ | По умолчанию | |
|---|---|---|
| `MasterTargetName` | `club-master` | имя таргета (без `games-`) |
| `MasterExtentName` | `clubsrv-master` | экстент мастер-тома на запись |
| `MasterDriveLetter` | `M` | буква на ПК суперклиента; `G` (= `DriveLetter`) — мастер-том вместо тома библиотеки, помощник 1.5.1+ (см. выше). Одна буква D…Z (как и `DriveLetter`; регистр и пробелы не важны, иное — ошибка при старте сервера) |

## Проверено и не проверено

- Проверено тестами: поддельный TrueNAS с правилами настоящего (секрет 12..16, CHAP-тег в использовании не
  удаляется, удаление группы открывает таргет всем), сервер и помощник на поддельной Windows — полный цикл открыть →
  M: на запись → закончить → сброс и отключение → закрыто; принудительное закрытие; повторное открытие с новым
  секретом; отказы; IQN, появившийся после старта помощника, доходит до сервера без перезапуска помощника.
- Проверено на стенде (2026-10-02, Windows 11, помощник 1.4.0): `Get-InitiatorPort … ConnectionType -eq 'iSCSI'`
  даёт IQN Microsoft-инициатора, но только при запущенной службе MSiSCSI. В Windows она по умолчанию остановлена, а
  помощник запускал её лишь при подключении тома, и на новом стенде IQN не появлялся никогда; к тому же пустой IQN
  запоминался до перезапуска помощника. Исправлено в 1.4.1: служба запускается перед чтением IQN (ожидание до
  10 с), IQN читается коротким опросом со следующего такта после старта (регистрация его не ждёт), пустой IQN
  перечитывается не чаще раза за такт с паузой, растущей до 10 минут (полный опрос фактов не повторяется), пока IQN
  нет — предупреждение в журнале Windows.
- [ГИПОТЕЗА] `Connect-IscsiTarget -AuthenticationType ONEWAYCHAP` с секретом 16 символов; `Write-VolumeCache` +
  `Set-Disk -IsOffline` при открытых файлах отказывает, а не отключает насильно — проверить на стенде.
- [ГИПОТЕЗА] `iscsi.auth.update` принимает частичное обновление `{secret}` (как остальные update в middleware).

## Проверка на стенде

1. Помощник 1.4.1+ на ПК администратора (MSiSCSI можно не трогать — помощник запустит её сам) → в течение ~1 мин он
   в списке «Открыть для правки» (IQN читается со второго такта после старта службы).
2. Открыть → через ~30 с на ПК диск `M:` на запись; с другого ПК вход в `club-master` отклоняется (неверный CHAP
   и чужой IQN). `iscsi.target.query` — группа с одним IQN, `authmethod: CHAP`.
3. Поставить игру на `M:` через лаунчер; «Закончить правку» → `M:` исчезает, в панели «закрыт»; «Опубликовать» → на
   ПК игроков новая версия с этой игрой.
4. Открыть файл на `M:` и нажать «Закончить правку» → помощник сообщает ошибку, том остаётся, сервер ждёт.
5. Выключить ПК суперклиента с открытым томом → «Отключить принудительно» → «закрыт», пометка о недописанности,
   публикация спрашивает подтверждение.

Мастер-том на букве библиотеки (`Library:MasterDriveLetter=G`, помощник 1.5.1 на ПК правки):

6. ПК правки с личным диском на G:, лаунчеры закрыты → «Открыть» → в течение такта G: — мастер-том на запись
   (`Get-Disk | ? BusType -eq iSCSI` — диск `club-master`, личного `games-seat-NN` нет); в журнале «Приложение»
   `Personal games disk … flushed and taken offline`, `Library target … disconnected`, затем `Master volume … connected`.
   У других ПК G: — по-прежнему их личный диск.
7. Лаунчер ставит игру на `G:\…` → после публикации на месте тот же лаунчер видит игру по тому же пути.
8. Открыть файл на G: (или оставить лаунчер с файлами на G:) и нажать «Открыть» → личный диск остаётся, на экране
   «Библиотека игр» у мастер-тома ошибка `drive letter G: is held by the library volume: …` (та же — в подсказке к
   отметке мастер-тома в списке рабочих станций); закрыть файл → G: переходит к мастер-тому.
   [ГИПОТЕЗА, как у мастер-тома: `Set-Disk -IsOffline` при открытых файлах отказывает, а не отключает насильно.]
9. «Закончить правку» → мастер-том уходит, в том же такте на G: снова личный диск.
10. Открыть файл на G: мастер-тома → «Закончить правку» (ждёт) → «Отключить принудительно» → `Get-IscsiSession`
    показывает `club-master` с `IsConnected False`, G: на месте; через ~2 минуты помощник пытается отключить сессию
    (в панели у мастер-тома отказ Windows); закрыть файл → сессия уходит, на G: снова личный диск.
    [ГИПОТЕЗА: Windows восстанавливает сессию удалённого таргета, а не снимает её сама; `Disconnect-IscsiTarget` такую
    сессию отключает.]
