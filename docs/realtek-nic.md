# Realtek RTL8111H на гибридах Mirage: драйвер rt640x64

Скрипт — `scripts/golden/install-realtek-nic.ps1`, выкладка — `scripts/golden/publish-realtek-nic.sh`.

## Симптом

Зона Mirage — 5 гибридов (Ryzen 5600X; 4× MSI B450 TOMAHAWK MS-7C02, 1× MSI X470 GAMING PLUS MAX MS-7B79), встроенная
карта Realtek RTL8111H — `PCI\VEN_10EC&DEV_8168` (`REV_15`, `SUBSYS_7C021462` / `SUBSYS_7B791462`). Windows 11 Pro
(10.0.26300) ставит на неё свой драйвер «Realtek PCIe GbE Family Controller» **1.0.0.14** — `rtcx21x64.sys`
(NetAdapterCx, компонент `Microsoft.Windows.Ethernet.Client.Realtek.Rtcx21x64~~~~0.0.1.0`, дата драйвера 2017-08-10).

Раз в несколько минут или часов карта **перестаёт принимать** пакеты, а линк остаётся поднятым на 1 Гбит/с (события 27
«линк упал» нет). Иногда через ~3 минуты оживает сама, иногда — только после переподключения кабеля. Только эти 5 ПК,
у всех один и тот же драйвер. Для гибрида это значит ещё и отвал игровых дисков G:/H: (iSCSI с TrueNAS; помощник
переподключает их сам, но игра с них падает или зависает).

## Решение

Драйвер Realtek NDIS **`rt640x64.sys`** (пакет MSI `realtek_pcielan_w11.zip`, Realtek 10.79.50.1003 с
`DriverVer 10/03/2025,10.079.50.1003`, или новее, например 10.80.50; версия нигде не зашита — берётся из INF набора) и
выключенное энергосбережение карты:

| Что | Значение |
|---|---|
| `*EEE`, `AdvancedEEE`, `EnableGreenEthernet`, `GigaLite`, `PowerSavingMode` | `0` (только если у драйвера есть такое ключевое слово) |
| «Разрешить отключение этого устройства для экономии энергии» | выкл. (`AllowComputerToTurnOffDevice = Disabled`; WoL не трогается) |
| PCIe ASPM активной схемы питания | выкл. (`powercfg ... SUB_PCIEXPRESS ASPM 0`, от сети и от батареи) |
| `*FlowControl`, `*SpeedDuplex`, `*JumboPacket`, WoL | не меняются, только печатаются |

`rt640x64` по рангу выше встроенного (точный `SUBSYS` и более новая дата), поэтому `pnputil /add-driver … /install` его
ставит; на случай, если нет, — принудительная установка (`UpdateDriverForPlugAndPlayDevices`, `INSTALLFLAG_FORCE`).
Встроенный драйвер **не удаляется**: откажет `rt640x64` — у карты останется драйвер.

## Доказательства

Скрипт до любых изменений печатает (только чтение) события журнала System за 7 дней — число и время последнего:

| Событие | Что значит |
|---|---|
| HAL 15 (`Microsoft-Windows-HAL`) | ошибка DMA remapping / IOMMU |
| NDIS 10400 / 10401 | Windows сбрасывает зависшую карту / сброс закончен |
| Tcpip 4202 | карта отключилась от сети |
| 27 / 32 от `rtcx21x64` / `rt640x64` | линк упал / поднялся |
| NCSI (System и `NCSI/Operational` 4042) | смена доступности сети |

Плюс последние 15 событий карты по времени. Фото этого экрана до замены — для сравнения через неделю.

## Выкладка (машина разработки)

```bash
unzip realtek_pcielan_w11.zip -d /tmp/rtl
scripts/golden/publish-realtek-nic.sh /tmp/rtl          # или путь к нужному rt640x64.inf
```

Ищет `rt640x64.inf` для Win10/Win11 x64 (папки WinPE пропускаются; нашлось несколько — дать путь к INF), проверяет, что
он перечисляет `DEV_8168` и собран для NTamd64, печатает `DriverVer`, собирает каталог и все файлы из
`[SourceDisksFiles]` / `[SourceDisksFiles.amd64]` (раскладка должна быть плоской) и выкладывает:

- `/srv/club/pxe/tools/realtek-nic/` — файлы драйвера байт в байт, `install-realtek-nic.ps1` (CRLF) и `SHA256SUMS`;
- `/srv/club/pxe/tools/install-realtek-nic.ps1` — сама команда (те же байты).

В конце сверяет sha256 на VM и каждый файл по HTTP.

## Запуск на ПК

Вход «Club», Win+X → «Терминал (администратор)», игры с G:/H: закрыты:

```powershell
irm http://192.168.1.201:5080/pxe/v1/files/tools/install-realtek-nic.ps1 | iex
```

Шаги: карты и их драйвер → события за 7 дней → набор в `C:\ClubDrivers\realtek-nic` (сверка SHA256; всё скачивается
**до** замены драйвера, при замене сеть пропадает на 5–30 с) → вопрос и замена драйвера (уже `rt640x64` не старше
набора — без замены) → линк, IPv4 и `http://192.168.1.201:5080/health` → настройки → сторож (вопрос, затем пробный
запуск) → итог OK/WARN/FAIL и вопрос о перезагрузке (есть FAIL — по умолчанию «нет»). Настройки карты вступают в силу
после перезагрузки. Журнал — `C:\ClubDrivers\realtek-nic\logs\<ПК>-<время>.txt`.

Набор обновляется целиком или никак: изменившиеся файлы сначала скачиваются в `<имя>.part` и сверяются, на место
(`SHA256SUMS` — последним) встают, только когда сверены все. Оборвалось скачивание — старый набор остаётся
согласованным, сторож может из него ставить драйвер.

Итог замены — по состоянию устройства, а не только по `DriverFileName`:

| Итог | Что значит | Что делает скрипт |
|---|---|---|
| OK | карта на `rt640x64.sys` | настройки, сторож |
| WARN «completes at the reboot» | pnputil 3010 / «нужна перезагрузка» / код 14: устройство уже на пакете `rt640x64`, до перезагрузки работает прежний драйвер | сторож ставится (настройки карты он выставит при загрузке), перезагрузка — по умолчанию «да» |
| FAIL «set up but did not start» | устройство на `rt640x64`, но сетевой карты нет или код ошибки (10 и т. п.) — сети, скорее всего, нет | больше ничего; перезагрузить, не помогло — локальный откат (ниже), он работает без сети |
| FAIL «still NOT on rt640x64» | драйвер не встал; «прежний драйвер работает» пишется, только если проверено, что карта Up на прежнем файле | больше ничего; откат — тоже локальной командой |

Без вопроса о перезагрузке: `& ([scriptblock]::Create((irm http://192.168.1.201:5080/pxe/v1/files/tools/install-realtek-nic.ps1))) -NoReboot`.

На бездиске (системный диск по iSCSI) скрипт отказывается: драйвер живой загрузочной карты менять нельзя.

С флешки (без сети): на флешку кладётся опубликованный набор `realtek-nic\` (те же файлы и SHA256SUMS, что на сервере)
и рядом `realtek-nic-run-as-admin.cmd` — он запускает `realtek-nic\install-realtek-nic.ps1` файлом. Скрипт, запущенный
файлом из папки с SHA256SUMS (не из `C:\ClubDrivers\realtek-nic`), берёт набор из этой папки, а не с сервера; сверка та же.
2026-11-03 на флешку CLUB это записано в `club\`.

## Проверка

```powershell
Get-NetAdapter | fl Name,DriverFileName,DriverVersionString,DriverProvider
```

Должно быть `DriverFileName : rt640x64.sys`, версия из `DriverVer` набора, поставщик Realtek. Ещё: задача
`ClubRealtekNicGuard` в планировщике, `C:\ClubDrivers\realtek-nic\logs\guard.log` после перезагрузки. Через неделю —
снова тот же скрипт (он же печатает события; при уже стоящем драйвере ничего не меняет) и сравнить счётчики.

## Сторож

Задача `ClubRealtekNicGuard`: SYSTEM, при загрузке (через 30 с), наивысшие права:

```
powershell -NoProfile -ExecutionPolicy Bypass -File C:\ClubDrivers\realtek-nic\install-realtek-nic.ps1 -Guard
```

Обновление Windows (feature update) может вернуть встроенный драйвер. Сторож без сети и без вопросов: сверяет локальные
файлы с локальным `SHA256SUMS`; карта не на `rt640x64.sys` — ставит его из локальных файлов (pnputil, при неудаче —
принудительно); `rt640x64` уже стоит и ждёт перезагрузки — ничего не делает; настройки сверяет каждую загрузку у карты,
работающей на `rt640x64`, и меняет только отличающиеся — карта перезапускается один раз и только если значение
действительно поменялось (не держится — WARN в журнале, без перезапуска). Журнал — `guard.log` (больше 256 КБ —
остаются последние 1500 строк).

Копия скрипта для сторожа — **файл из набора на сервере** (он есть в `SHA256SUMS`), а не текст, выполненный через
`irm | iex`: под iex своего текста у скрипта нет, а так сторож запускает ровно то, что сверено по SHA256, и сверяет
себя сам при каждом запуске. Права папки — только SYSTEM и Administrators, и у `C:\ClubDrivers` тоже; **владелец**
`C:\ClubDrivers`, `realtek-nic` и всего внутри — тоже Administrators (`icacls /setowner *S-1-5-32-544`, не вышло —
`takeown /A`). Иначе пользователь (например, player), заранее создавший эту папку, остался бы её владельцем, вернул бы
себе права и подложил свой скрипт, который сторож запустил бы от SYSTEM. Ссылка (junction/symlink) вместо папки или
внутри неё — установка отказывается. Перед регистрацией задачи владелец ставится и проверяется по SID ещё раз: не
Administrators/SYSTEM — сторож не ставится (FAIL).

## Откат

```powershell
& ([scriptblock]::Create((irm http://192.168.1.201:5080/pxe/v1/files/tools/install-realtek-nic.ps1))) -Undo
```

Без сети (карта мертва) — из локальной копии:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\ClubDrivers\realtek-nic\install-realtek-nic.ps1 -Undo
```

Удаляет задачу-сторож, находит пакеты `oemNN.inf` с исходным именем `rt640x64.inf` (`Get-WindowsDriver -Online`, при
ошибке — база драйверов в реестре; вывод pnputil не разбирается — он на языке Windows). Перед вопросом проверяет, что
карте есть куда вернуться: компонент встроенного драйвера `Installed` или `rtcx21x64.sys` в хранилище драйверов. Нет ни
того, ни другого — WARN и по умолчанию «нет» (иначе карта осталась бы без драйвера и без сети). Затем удаляет пакеты
`pnputil /delete-driver oemNN.inf /uninstall /force` — карта возвращается на встроенный `rtcx21x64` (не вернулась за
20 с — `pnputil /scan-devices`). ASPM и питание карты **не** возвращаются — скрипт печатает команды для этого (старые
значения — в журнале установки). Папка `C:\ClubDrivers\realtek-nic` остаётся.

Карта после отката осталась без драйвера и сети — вернуть `rt640x64` из локальных файлов (сеть не нужна; итог — в
`C:\ClubDrivers\realtek-nic\logs\guard.log`):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\ClubDrivers\realtek-nic\install-realtek-nic.ps1 -Guard
```

или напрямую `pnputil /add-driver C:\ClubDrivers\realtek-nic\rt640x64.inf /install`.

## Перезаливка и образ гибрида

Перезаливка гибрида образом убирает всё: драйвер, настройки, задачу, папку. После перезаливки ПК Mirage — снова та же
команда. Позже `rt640x64` и эти настройки нужно добавить в образ гибрида (prepare-hybrid / seal-hybrid), тогда скрипт
на ПК станет не нужен.
