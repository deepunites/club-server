# Установка шелла ClubShell на ПК клуба

Шелл — сторонний продукт (GitHub `Nightcall7442/club-shell`): служба-агент `ClubShellAgent`, киоск-оболочка для
игрока, касса `https://clubshell-admin-production.up.railway.app/`, сервер на Railway. Наша сторона не меняется:
помощник `ClubDisklessHelper` (1.6.0; с 1.7.0 — ещё и сохранения игрока по каналу для шелла) по-прежнему подключает G:
«Online Games» и H: «Offline Games», шелл их не трогает.
Набор для установки — `scripts/shell/`; на гибрид он приходит по сети клуба одной командой (`get-shell-kit.ps1`).
Пилот — PC-01 (2026-11-01, уроки — в конце раздела «Установка на гибрид»), дальше остальные гибриды; бездиск — тем же
набором, один раз в эталон в режиме мастера (раздел «Бездиск»).

## Что ставим

Релиз **v1.0.18** (2026-10-27; `main` новее только кассой — агент и установщик те же), файл
**`ClubShellSetup-1.0.18.exe`** — 75 490 102 байт, SHA256
`1d23dee18e17be03a19801cd2d7cd1f8c8fde7b8d4e83a2b5ba6785eaf46a1cf`
(страница релиза: `https://github.com/Nightcall7442/club-shell/releases/tag/v1.0.18`). Это бандл: WebView2 (если его
нет) + `ClubShell-1.0.18.msi` (агент и оболочка). Свой загрузчик WebView2 у бандла устарел (установка падает с
`0x80091007`), поэтому набор ставит WebView2 заранее. Сборка **не подписана** (SmartScreen «неизвестный издатель» —
норма; скрипт сверяет SHA256 и снимает метку «из интернета»; Smart App Control её блокирует — выключить).
`ClubShell-Shell-1.0.18.msi` / `-setup.exe` — только оболочка, без агента: **не ставить**.

| | |
|---|---|
| Адрес сервера для агента | `https://clubshell-server-production.up.railway.app` (API; адрес кассы — другое приложение) |
| Учётка киоска | `player` — создаёт агент: обычный пользователь, случайный пароль, автовход |
| Администратор гибрида | `Club` — остаётся администратором; **до игроков — пароль** |

Файл кассы «Зал и устройства» → «Установка на ПК» (`clubshell-install.cmd`) для наших ПК **не используем**: поле киоска
там по умолчанию `club` (= наш `Club`: агент откажется, и игрок останется на рабочем столе администратора), ключ ПК
лежит в самом файле и уходит в командную строку установщика, он берёт «последний» релиз с GitHub, а перенаправление
папок игрока, корни библиотек и путь Steam не задаёт.

## Набор `scripts/shell/`

| Файл | Что делает |
|---|---|
| `get-shell-kit.ps1` (по сети, `irm … \| iex`) | номер места и имя `PC-NN`, Smart App Control, брандмауэр LAN-игр и ClubMaxRefresh, набор в `C:\ClubShellKit` со сверкой SHA256, запуск установки; на мастере бездиска сам включает режим эталона (`-Golden`) |
| `seal-golden.ps1` (из `scripts/golden/`) | последний шаг мастера эталона: очистка помощника и ClubShell, проверки эталона с шеллом, удаление `C:\ClubShellKit`, выключение |
| `shell-preflight-run-as-admin.cmd` → `shell-preflight.ps1` | проверка ПК, только чтение (PASS/WARN/FAIL) |
| `shell-install-run-as-admin.cmd` → `shell-install.ps1` | (с флешки — сначала копирует набор в `C:\ClubShellKit`) проверка, WebView2, `agent.json`, установка, проверки, пароль Club, PIN, касса; после одобрения — киоск и перезагрузка в него |
| `kiosk-on-run-as-admin.cmd` → `kiosk-on.ps1` | киоск после одобрения: `Club` — администратор и с паролем (пустой — предложит задать), автозапуск выкл., шелл в шаблоне профиля, профиль `player` и автовход в него |
| `enable-kiosk-autologon.ps1` | скрипт разработчика шелла (его запускает `kiosk-on`): профиль киоска, помехи автовходу, перезапуск агента, ждёт «shellReplacement applied» |
| `seal-default-profile.ps1` | шелл ClubShell в шаблоне профиля `C:\Users\Default`; `-Undo` — убрать |
| `disable-autoplay.ps1` | автозапуск (AutoPlay/AutoRun) выкл. для всех дисков и пользователей |
| `0b-webview2-run-as-admin.cmd` → `install-webview2.ps1` | WebView2 Runtime отдельно (`shell-install` ставит его сам) |
| `set-club-password-run-as-admin.cmd` → `set-club-password.ps1` | пароль `Club` (вводит владелец, «срок не ограничен») |
| `set-shell-pin-run-as-admin.cmd` → `set-shell-pin.ps1` | PIN панели администратора киоска (6–12 цифр) |
| `shell-set-key.ps1` | замена ключа ПК у стоящего ClubShell без переустановки |
| `shell-agent-diag-run-as-admin.cmd` → `shell-agent-diag.ps1` | состояние агента: служба, сервер, регистрация, журнал; только чтение |
| `shell-uninstall-run-as-admin.cmd` → `shell-uninstall.ps1` | откат: удаление, остатки, шаблон профиля, киоск, данные, автовход `Club` |
| `publish-kit.sh` | (машина разработки) выкладывает набор на сервер клуба |

`enable-kiosk-autologon.ps1` — копия байт в байт из `Nightcall7442/club-shell`, `tools/scripts/` (коммит `9b0ea42`;
тот же файл лежал на VM и сработал на PC-01): UTF-8 с BOM, CRLF, вывод по-русски. Не править; новая версия — взять файл
заново. По умолчанию у него киоск `club` (= наш `Club`), поэтому только через `kiosk-on` — всегда с `-KioskUser player`.

Ключ ПК, пароль и PIN вводит владелец на ПК (ввод скрыт); скрипты их не печатают и не пишут в журналы. Журналы —
`C:\ClubShellKit\logs`.

Почему установка устроена так (подробно — в шапках скриптов):

- **`agent.json` пишется до установщика.** MSI видит готовый файл и не трогает его, поэтому ключ ПК не передаётся в
  командной строке (`CLUBAPIKEY` попал бы в командную строку процесса и журнал MSI). Файл — только для SYSTEM и
  администраторов; при первом старте агент переносит ключ в `secure\club.key` (DPAPI) и стирает его в `agent.json`.
- **Перенаправление папок игрока выключено** в этом же файле: по умолчанию агент при первом старте уводит Рабочий стол,
  Документы и Загрузки игрока на диск с наибольшим свободным местом — у нас это H: или G: (личные диски, сбрасываются),
  и выключение потом этого не отменяет.
- Корни библиотек `G:\Steam` и `H:\` (игры владельца — прямо в `H:\<Игра>`), Steam — `G:\Steam\steam.exe`,
  автообновление выключено (манифест 1.0.18 не подписан, агент его всё равно отвергнет), свой монтаж дисков у агента
  выключен.
- Установщик: `ClubShellSetup-1.0.18.exe /quiet /norestart KIOSKUSER=player INSTALLSHELL=1`. Никаких `SERVERURL`,
  `CLUBAPIKEY`, `INSTALLDISKLESS`/`DISKLESS*` (в релизе помощника нет, наш помощник не трогаем).
- **WebView2 — до установщика** (`install-webview2.ps1`: официальный загрузчик Microsoft, проверка подписи).
- **Киоск — отдельным шагом после одобрения** (`kiosk-on`). Автовход в `player` — часть политики `shellReplacement`.
  Она включена и в политике из MSI (`Agent\config\policies.example.json`, её агент применяет до одобрения), и в
  политике кассы, но агент сначала пишет шелл в профиль `player` и падает, пока профиля нет (в киоск никто не входил):
  на PC-01 автовход не переключился ни до, ни после одобрения. Поэтому `kiosk-on` создаёт профиль сам — и именно
  после одобрения: до него киоск включился бы на политике из MSI, а касса не начала бы на ПК сеанс. Порядок: `Club` —
  администратор и с паролем → автозапуск выкл. → шелл в шаблоне профиля → профиль `player` (из уже готового шаблона) и
  перезапуск агента — шелл в профиль и автовход пишет он сам.

## Сервер клуба: набор по сети

Файлы отдаёт club-server (VM `192.168.1.201`) по HTTP, только в сети клуба:
`http://192.168.1.201:5080/pxe/v1/files/tools/<имя>` = `/srv/club/pxe/tools/<имя>` на VM.

- `tools/shell-kit/` — весь набор (`scripts/shell/*.ps1`, `*.cmd`), `scripts/golden/seal-golden.ps1` (байт в байт),
  `ClubShellSetup-1.0.18.exe` и `SHA256SUMS`;
- `tools/get-shell-kit.ps1`, `tools/seal-default-profile.ps1`, `tools/disable-autoplay.ps1` — для запуска по сети;
- там же — `install-lan-firewall.ps1`, `install-max-refresh.ps1`, `update-helper-net.ps1` (из `scripts/golden/`).

Выкладывает Claude с машины разработки: `scripts/shell/publish-kit.sh`. Он сверяет SHA256 установщика, переводит
`.ps1`/`.cmd` в CRLF (только в выкладке), пишет `SHA256SUMS`, ставит файлы через `sudo` и сверяет SHA256 на VM и по
HTTP. После каждой правки набора — запустить снова.

`SHA256SUMS` защищает от ошибок передачи и недокачки, **не от подмены**: список, файлы и сам `get-shell-kit.ps1` идут
по HTTP с одного сервера, как и любая команда `irm … | iex` клуба. Устройство в той же сети (пул 192.168.1.20–99:
телефоны, Wi-Fi) могло бы подменить ответы сервера (ARP), и подменённые скрипты остались бы в `C:\ClubShellKit`.
Риск тот же, что у всех `irm … | iex` клуба (и `update-helper-net` — HTTP со сверкой SHA256); отдавать набор по HTTPS с
CA клуба — открытый вопрос.

## Установка на гибрид

Шаги 1–6 — на каждом гибриде, по одному; пароль `Club` и PIN — на каждом (один на все — решение владельца).

### 0. Один раз

1. **Ключ ПК клуба Deagle** — суперадмин ClubShell → «Новый ключ для ПК». **Не** `Club__EnrollmentKey` с Railway: это
   ключ первого клуба «ClubShell», PC-01 с ним зарегистрировался там, и в кассе Deagle его не было (замена без
   переустановки — `shell-set-key.ps1`). Держать у владельца, в чат и файлы не класть.
2. **Касса** («Зал и устройства» → «Политика ПК»): `webFilter.dnsServers` — `[]`, `blockResolvedIps` — `false` (иначе
   агент пропишет DNS на все адаптеры). Решить про USB (раздел «USB»). Зоны — финальные названия, написанные так же,
   как в зонах игр каталога (регистр важен). ПК в кассе **вручную не добавлять**.
3. **Набор на сервере клуба** — `publish-kit.sh` (раздел выше).

### 1. Периферия — под `Club`, до шелла

- Программы мыши, клавиатуры, гарнитуры — под `Club`, установщиком «для всех пользователей»; потом выключить их в
  Диспетчере задач → «Автозагрузка».
- Всё, что делается с флешки (драйверы, BIOS), — тоже **до** установки: после неё флешки на этом ПК не работают.
- Образ h1d/h1e (у h1b/h1c — срок пароля 42 дня: сначала перезалить — перезаливка стирает шелл).

### 2. Номер — в панели (Claude)

Номер окончательный до установки: ClubShell берёт его из имени Windows `PC-NN` **один раз**, при первой регистрации.
Сначала Claude перенумеровывает ПК в панели club-server (личные диски `games-seat-NN` / `solo-seat-NN`), потом имя
Windows меняет `get-shell-kit` (шаг 3). Разошлись номер дисков и имя — проверка даёт FAIL, установки нет.

### 3. Одна команда

Под `Club`: Win+X → «Терминал (администратор)»:

```
irm http://192.168.1.201:5080/pxe/v1/files/tools/get-shell-kit.ps1 | iex
```

1. Номер места (Enter — оставить нынешний `PC-NN`). Другой номер — переименует ПК в `PC-NN` и сразу перезагрузит;
   после перезагрузки (снова `Club`) — **та же команда ещё раз**.
2. Smart App Control включён — подскажет, где выключить: «Безопасность Windows» → «Управление приложениями/браузером»
   → «Интеллектуальное управление приложениями» → «Выкл.». Выключить, ответить `y`. До брандмауэра: `ClubMaxRefresh`
   — тоже неподписанный exe.
3. Брандмауэр для LAN-игр и `ClubMaxRefresh` — ставит, если их нет (игрок — не администратор: без брандмауэра каждое
   окно «Разрешить доступ» создаёт правило-блокировку, LAN-игры не видят сервер).
4. Набор в `C:\ClubShellKit` (сверка SHA256; установщик 72 МБ — только первый раз).
5. Запускает установку (шаг 4) в этом же окне. Напоследок смотрит автовход: киоск не включён — жёлтая строка
   `the kiosk is NOT on yet` (ПК не готов, см. ниже «Не одобрен»).

Повторный запуск безопасен. ClubShell уже стоит — установку не повторяет, предлагает включить киоск.

### 4. Установка

`shell-install` по ходу спросит:

1. продолжать ли при WARN проверки. Ожидаемый — пустой пароль `Club` (`y`: он задаётся здесь же). Включённая учётка
   «Administrator» (встроенная; в русской Windows — «Администратор») — тоже WARN: лучше `n`, выключить
   (`net user Administrator /active:no`) и запустить команду снова;
2. WebView2 ставит сам, если его нет (нужен интернет);
3. **ключ ПК** — ключ Deagle (шаг 0); вставка — правой кнопкой, на экране ничего не видно;
4. после установки — **пароль `Club`** (дважды; от 8 символов; записать туда, где игроки не увидят) и **PIN**
   администратора киоска (6–12 цифр, дважды);
5. ждать ли одобрения в кассе (`y`) — Claude одобряет (шаг 5), скрипт сам это видит;
6. одобрен — включает киоск (`kiosk-on`; строки скрипта разработчика — по-русски, до 3 минут) и спрашивает
   `Reboot now into the kiosk?` — `y`. Есть FAIL — по умолчанию `n`: сначала фото окна, перезагрузка — когда FAIL
   разобраны (после неё исправлять — только через Shift → `Club`).

Итог — строки PASS/WARN/FAIL: агент работает, ключ ушёл из `agent.json`, `player` создан и не администратор, `Club` —
администратор, перенаправления на G:/H: нет, помощник и G:/H: на месте, DNS не изменился, ПК одобрен, киоск включён.
Автовход до одобрения не переключается — это строка для сведения, не WARN.

Не одобрен за 10 минут (или ответ `n`) — WARN `kiosk not on yet`. После одобрения:
`C:\ClubShellKit\kiosk-on-run-as-admin.cmd` → «Запуск от имени администратора» (или снова команда `get-shell-kit` —
предложит киоск). До этого автовход идёт в `Club` со старым паролем: после нового пароля `Club` перезагрузка
останавливается на экране входа — войти `Club` с новым паролем. Пропущенные пароль и PIN —
`set-club-password-run-as-admin.cmd` и `set-shell-pin-run-as-admin.cmd` из `C:\ClubShellKit`. С пустым паролем `Club`
`kiosk-on` киоск не включает (предложит задать пароль), как и когда `Club` — не администратор.

### 5. Касса (Claude)

«Зал и устройства»: появился ПК с именем `PC-NN`, «Обслуживание» включено.

1. Номер = NN из имени Windows (если нет — номер занят другим ПК; исправить номер вручную).
2. Зона.
3. «Обслуживание» **выключить** — это одобрение. Через минуту агент регистрируется и получает политику кассы.

**Без пароля `Club` игроков не пускать:** Shift при загрузке пропускает автовход в киоск, и на экране входа `Club` с
пустым паролем — полный администратор.

### 6. Проверка игроком

После перезагрузки ПК сам входит в `player`, на экране — оболочка ClubShell. Проверить:

- клавиша Win ничего не открывает (Пуска нет), окна «Автозапуск» нет (G: и H: подключаются после входа);
- игры G:\Steam, H: и Riot видны как установленные и запускаются; CS2/CS 1.6 по локалке (создать сервер и зайти с
  соседнего ПК);
- Alt+Tab, Ctrl+Shift+Esc заблокированы; Ctrl+Alt+Shift+A → PIN открывает панель администратора; флешка не открывается;
- **короткая сессия** — начать и закончить в кассе. После неё агент удаляет профиль `player`, Windows создаёт его
  заново: проверить ещё раз — нет Пуска, нет «Автозапуска», оболочка ClubShell.

### Без сети клуба: флешка

Сервер клуба недоступен — флешка, папка `ClubShellKit` = все файлы `scripts/shell/` + `ClubShellSetup-1.0.18.exe`;
правой кнопкой `shell-install-run-as-admin.cmd` → «Запуск от имени администратора». Лаунчер копирует набор в
`C:\ClubShellKit` и работает оттуда; WebView2, установка и киоск — так же. Чего он не делает: имя Windows (сначала номер
в панели, потом `Rename-Computer -NewName PC-NN -Force -Restart` — проверить написание; без перезагрузки — FAIL
проверки), брандмауэр LAN-игр и
`ClubMaxRefresh` (WARN проверки; ставятся только по сети). Интернет нужен всё равно (сервер ClubShell, WebView2). После
установки флешка на этом ПК не читается.

### Шаблон профиля и автозапуск

- `seal-default-profile.ps1` пишет в `C:\Users\Default\NTUSER.DAT` те же значения `Shell`, что агент пишет в профиль
  киоска. Нужен из-за сброса профиля (`resetProfileOnLogout`, по умолчанию вкл.): после каждой сессии агент удаляет
  профиль `player`, Windows создаёт его из шаблона, и без шелла в шаблоне запускается explorer — Пуск, «Автозапуск»
  поверх киоска (агент закрывает его только через 30 с после входа). Касается каждой новой учётки: новый администратор
  тоже получит шелл. Копия нетронутого шаблона — `C:\ClubShellKit\backup\default-NTUSER.DAT`. Ставит `kiosk-on`, до
  профиля `player`; вручную — только между сессиями.
- **`-Undo`** — если в кассе выключили замену оболочки (`shellReplacement`) или ClubShell убирают (`shell-uninstall`
  делает это сам):
  `& ([scriptblock]::Create((irm http://192.168.1.201:5080/pxe/v1/files/tools/seal-default-profile.ps1))) -Undo`
- `disable-autoplay.ps1` — HKLM-политика «выключить автозапуск» для всех дисков и пользователей. Ставит `kiosk-on`;
  удаление шелла её не снимает — безвредно.

### Уроки PC-01 (2026-11-01)

- **WebView2:** бандл 1.0.18 сам качает загрузчик WebView2 и сверяет его хэш со своим; Microsoft файл обновила →
  `0x80091007`. Теперь `shell-install` ставит WebView2 заранее.
- **Профиль и автовход:** после установки и одобрения агент не создал профиль `player` и не переключил автовход; после
  пароля `Club` ПК встал на экране входа (автовход шёл в `Club` со старым пустым паролем). Помог
  `enable-kiosk-autologon.ps1 -KioskUser player` — теперь это шаг `kiosk-on`.
- **Пуск после сброса профиля:** новый `player` из шаблона без шелла → explorer, Пуск, окно «Автозапуск» поверх
  киоска. Теперь `seal-default-profile` и `disable-autoplay` (в `kiosk-on`).
- **Чужой ключ:** `Club__EnrollmentKey` — ключ первого клуба «ClubShell», PC-01 попал туда. Ключ Deagle — у суперадмина,
  «Новый ключ для ПК».
- **Лишний администратор:** включённая встроенная учётка «Administrator» — WARN проверки; выключить до установки.
- **Имя:** вручную владелец один раз ошибся в имени — теперь имя по номеру ставит `get-shell-kit`.
- **Флешка:** после установки накопители USB выключены — набор приходит по сети.

## Выход из киоска и обслуживание

- **Панель администратора:** Ctrl+Alt+Shift+A (или Ctrl+Alt+Shift+F12) → PIN. Оттуда — перезагрузка/выключение и выход
  в «обслуживание»: 30 минут (до 480) оболочка не перезапускается, работают флешки, не действует запрет программ.
  «Выход в проводник» — это проводник **игрока** (без прав, без диспетчера задач), не администратора. Окно закрывается
  по времени, выходом из сеанса или перезапуском агента.
- **Рабочий стол администратора:** перезагрузка (панель или кнопка), сразу после логотипа Windows зажать **Shift** и
  держать до экрана входа → `Club` → пароль. В сеансе `Club` запрет программ не действует, а USB — да (выключен на всей
  машине, кроме окна обслуживания).
- В сеансе игрока запрещены `cmd`, `powershell`, `reg`, `regedit`, `taskmgr`, `mmc`, `*cheat*`, exe из Рабочего стола и
  Загрузок и др. (список — «Политика ПК»). Игра в каталоге должна указывать на `.exe`, не на `.bat`/`.cmd`.

## USB

Сразу после установки (ещё до одобрения) агент применяет политику из MSI: `USBSTOR Start=4` для **всей** машины и
извлекает вставленные флешки — и в сеансе `Club` тоже. Поэтому набор лежит на C: (`C:\ClubShellKit`) и приходит по
сети. После одобрения действует политика кассы `usb.allowStorage` (одна на клуб, для игроков тоже). Решение для
пилота: оставить как есть (флешки — только в окне обслуживания по PIN); если на дни раскатки нужно иначе — владелец
временно ставит `usb.allowStorage=true` в «Политика ПК». Удаление шелла возвращает `Start=3`.

## Нумерация и одобрение

- Номер берётся из имени Windows `PC-NN` при первой регистрации; потом — только вручную в кассе.
- Новый ПК — «ожидает одобрения» с «Обслуживание» вкл.; до одобрения у него нет политики кассы.
- Заранее добавленный в кассе ПК занимает номер: настоящий ПК тогда получит max+1. Не добавлять.
- Перезаливка гибрида стирает шелл → набор заново; в кассе это тот же ПК (то же железо — тот же HWID). Если на сервере
  `Agents__RegisterProof=enforce` — перед повторной установкой включить у ПК «Обслуживание» (окно 60 мин).

## Откат

`C:\ClubShellKit\shell-uninstall-run-as-admin.cmd` (под `Club`; Shift при загрузке). Спросит: удалить ClubShell;
удалить `player` с профилем; удалить данные `C:\ProgramData\ClubShell` (нужно перед чистой переустановкой); вернуть
автовход `Club` (иначе ПК встаёт на экране входа; спросит пароль `Club`, Enter — если пустой). Удаляет и MSI старых
пилотных сборок, убирает остатки (USB, секрет автовхода, задачи `\ClubShell\`), снимает шелл с шаблона профиля
(`seal-default-profile.ps1 -Undo`; автозапуск остаётся выключенным — безвредно), проверяет помощник (если удаление
старой сборки задело exe — возвращает его из копии). Касса: переставляем — ПК не удалять; убрали насовсем — удалить.
Другой путь отката — перезалить гибрид из панели club-server.

## Новая версия ClubShell

Набор её пока не ведёт: новый `ClubShellSetup-<версия>.exe /quiet /norestart KIOSKUSER=player
INSTALLSHELL=1` — `KIOSKUSER=player` каждый раз (иначе бандл передаст `club`), без `SERVERURL`/`CLUBAPIKEY`; `agent.json`
и регистрация сохраняются. Сначала сверить SHA256 нового файла с `SHA256SUMS.txt` его релиза.

## Нельзя

- `KIOSKUSER=club` / киоск `Club`; `removeFromPrivilegedGroups=true`; убирать `Club` из администраторов.
- Пускать игроков, пока у `Club` пустой пароль.
- `INSTALLDISKLESS`, `ADDLOCAL=DisklessHelper`, любые `DISKLESS*`; сборки ClubShell с помощником или пилотные CI;
  останавливать, переименовывать службу `ClubDisklessHelper` (агент уступает G:/H: именно ей).
- `dnsServers` и `blockResolvedIps` в «Политика ПК»; сон/гибернация/схемы питания с кассы на бездиск.
- Перенаправление папок и `paths.persistent` на G:/H:.
- `ENABLE-KIOSK.cmd` из club-shell. `enable-kiosk-autologon.ps1` — только из набора через `kiosk-on`, всегда с
  `-KioskUser player` (по умолчанию у него `club` = наш `Club`); с 1.0.18 сброс профиля игрока он не трогает.
- `clubshell-install.cmd` из кассы без `player`, без файла 1.0.18 рядом и без нашего `agent.json`.
- Ключ ПК — в файлах на ПК, флешке, в чате.

## Бездиск: шелл в эталон (режим мастера)

Шелл ставится в **эталон** один раз, в сеансе мастера; места получают его с публикацией — **все зоны бездиска сразу**
(5x5 26–35, Primer 36–46, потом Standart): эталон один на всех. Та же команда `get-shell-kit` сама видит сеанс
`…:diskless-master` и включает режим эталона (строка `GOLDEN MODE`): имя остаётся `USER`, без номера и
переименования, администратор — тот, кто вошёл (у эталона это не `Club`), в конце — без перезагрузки. На обычном месте
(`…:seat-NN`) набор останавливается до любых изменений (C: сбрасывается при загрузке).

Мастер — **ПК Primer с MSI B560** (например, бывший бездисковый PC-01), **не** нынешний PC-01: тот — гибрид Aura со
своей записью в кассе. Мастер регистрируется с HWID этого физического ПК (диск iSCSI в HWID не входит), поэтому его
запись в кассе и есть это место: одобрить как место, **не удалять**.

Что делает `seal-golden.ps1` с ClubShell (подробно — в его шапке): сначала проверки без изменений (имя `USER`, версия
1.0.18, `player` не входил и оболочка на мастере не запускалась, `profile-dirty.marker` нет, мастер одобрен, ключ ПК в
`secure\club.key` расшифровывается) — любой WARN: ничего не изменено. Потом очистка как у `prepare-image.ps1` из
club-shell v1.0.18 (сам `prepare-image.ps1` не нужен), но ключ ПК **остаётся** в `secure\club.key` (эталон без sysprep —
ключи DPAPI машины у мест те же), а `pcId`/`pcName`/`zone` мастера убираются из `agent.json`. Дальше проверки эталона с
шеллом (agent.json, PIN, политика в кэше, `player` и шелл в его профиле и в шаблоне Default, автовход, пароль
администратора и что он не учётка Microsoft, других включённых администраторов и учёток с пустым паролем нет — каждая
включённая учётка на экране входа всех мест, USB, схемы питания), удаление `C:\ClubShellKit`, выключение. USB — не
«как у Windows» (`prepare-image.ps1` ставит `USBSTOR Start=3`): C: мест сбрасывается при каждой загрузке, и Start из
образа действует до агента — USB-диск, вставленный до загрузки, подключался бы на каждом сеансе (агент извлекает только
съёмные тома, USB HDD/SSD — «несъёмные»). Поэтому Start — по политике кассы в кэше: `usb.allowStorage=false` → 4,
`true` → 3; поменяли USB в «Политике ПК» — в образ это попадёт со следующим `seal-golden` и публикацией. С шеллом и без
`seal-golden` снова выключает обновление Edge/WebView2 (службы `edgeupdate`, `edgeupdatem`, задания
`MicrosoftEdgeUpdate*`, как `fixes-v2.ps1`): `install-webview2.ps1` обновляет клиент EdgeUpdate, и тот заново включает
свои задания.

### Каждый следующий сеанс мастера (новые платы, драйверы)

- При загрузке держать **Shift** до экрана входа (иначе автовход в `player`), войти администратором эталона.
- USB выключен политикой агента: флешка — в окне обслуживания по PIN или `Stop-Service ClubShellAgent` + `USBSTOR
  Start=3` на время работы (`seal-golden` всё равно поставит Start по политике кассы в кэше: `usb.allowStorage=false`
  → 4).
- Агент мастера регистрируется снова; перед каждой публикацией — `seal-golden.ps1` (набор вернёт команда
  `get-shell-kit`; на вопрос про киоск — `n`).
- Сменили ключ ПК в кассе — места бездиска не зарегистрируются, пока не опубликован эталон с новым ключом
  (`shell-set-key.ps1` в сеансе мастера, `seal-golden`, публикация — в тот же день).
- Знакомство платы (копия с SSD) и эталон гибрида (`make-hybrid-ref.py`) берут снимки эталона уже с ClubShell —
  открытый вопрос: USB на SSD выключен агентом, лишняя запись в кассе; эталон гибрида — из снимка до шелла.

Открытые вопросы бездиска (SHELL_CHANGES в `deepunites/club-contracts`):

- C: сбрасывается — агент регистрируется заново при каждой загрузке; это допускает флаг «Без постоянного диска»
  (D-79), но неотправленные офлайн-события теряются, а под `enforce` быстрая перезагрузка даёт 403 до 90 с (п. 57):
  `Agents__RegisterProof` держать `audit`. Без интернета при загрузке место не работает (нет токенов и игроков в кэше).
- HWID: при сбое WMI на загрузке в HWID попадает iSCSI-диск → лишний ожидающий ПК (п. 48).
- `secure\club.key` из эталона на местах — по общему ключу DPAPI машины (нет sysprep), как `credentials.bin` помощника;
  на ClubShell не проверено до п. 8. Разработчику: перенос ключа в `agent.json` в `prepare-image.ps1` нам не нужен.
- `prepare-image.ps1` стирает `profile-dirty.marker` (п. 50) и оставляет `pcId` мастера в `agent.json` — у нас
  `seal-golden.ps1` вместо него.
- Номер мест не из имени (`USER`): MachineFeed (п. 22) не сделан — номера вручную.
- Сохранения офлайн-игр H: пропадают при перезагрузке (п. 75); каталог на ПК без H: (п. 74).
- Автообновление выключено: обновление шелла — новой версией в эталоне.
